# Web app

The app is a mobile-first map workspace written in TypeScript and Preact. It has two pages: a landing page at `/` and the map app at `/map`. The map app has five views (Coast, Conditions, History, Fleet and Reports), a brief beside or under the map, a layer rail, and a time dock. This page describes what the code does today (package version 0.8). The older Leaflet "classic" shell is removed.

## Run it locally

```bash
pnpm install --frozen-lockfile && pnpm build
node scripts/wrangler_config.mjs 00000000-0000-0000-0000-000000000000 skippercast-feeds wrangler.local.jsonc
npx --yes wrangler@4.142.0 dev --config wrangler.local.jsonc
```

Open `http://localhost:8787/`. `pnpm build` (`scripts/build-worker.mjs`, `vite.config.mjs`) builds the pages in `dist/*.html` with Vite into `dist/client` (hashed scripts and styles in `assets/`, one stylesheet per page, pages renamed with the build id, static data copied unchanged) and bundles the Worker into `dist/server`; see [Cloudflare](cloudflare.md). `scripts/check_client.mjs` checks the output, including that the heavy map and terrain libraries stay out of the first-paint imports. `wrangler dev` serves both, including the Worker's `/feeds/` and `/api/` routes. On an iPad, use the deployed HTTPS site.

## Pages and routes

- `/` serves `dist/landing.html` (entry `web/landing/main.tsx`; components in `web/landing/`). With an area parameter (`region`, `spot`, `place` and the other keys in `server/routes/assets.ts` `AREA_PARAMS`) it opens the map app instead, so shared links keep working.
- `/map` serves `dist/app.html` (entry `web/app/main.tsx`).
- `/coast` moves to `/map?presentation=3d`.
- Other pages in `dist/*.html` are static: sources, licenses, privacy, terms, the species-research page, `coast-readable.html`, `commercial-ais.html`, and the advisor and admin pages (`chat.html`, `my-data.html`, `upload.html`, `admin.html`).
- The deploy's smoke test opens `/`, `/map` and `/coast` (`scripts/smoke_test.sh`).

## State and the URL

`region`, `coast`, `view`, `target`, `hour`, `profile`, `day`, `layers`, `area`, `base` and `port` in the address are the source of truth (`URL_KEYS` in `web/state.ts`, which also lists the History and coast keys). Choosing a port, changing a view, picking a target or moving the time dock updates the address without a reload, and a shared link opens the same state. Region changes never reload the page in the map app (`configureStore({v2: true})` in `web/app/main.tsx`); `navigate()` in `web/state.ts` is the one place that decides. `?view=` names a masthead view (`coast`, `conditions`, `history`, `fleet`, `reports`); any other value is read as a map position `lat,lng,zoom`.

### Shared links

Share, beside the port control (`ShareControl` in `web/app/CommandBar.tsx`), builds one canonical link with `shareLink` in `web/share-link.ts` and hands it to the share sheet, else copies it, else shows it in a field to copy. The link is `/map?` with, in this order, `region` (or, over the coast with no region, `coast`: the address's own, else `central`, so a link always names its geography), `port`, `profile`, `day`, `hour` (when the address has one), `target` (when set), then whichever of `view`, `layers`, `base`, `presentation`, `current`, `habitat` and `spot` the address has. Nothing else is carried. `day` is the dock's local date, always written (today included), so the link means the same day later; a day past the forecast horizon is left out. Its title is `<Port> · <Sat Nov 7> · <Profile>`; neither the link nor the title carries a condition.

Opening a link shows its `port` when that port is listed in its `region` (`linkedPort` in `web/ports.ts`), else the saved home port, else the region's first port. Reading a link never saves a home port. Once the port directory loads, an unlisted, foreign or malformed `port` is removed from the address; a directory that fails to load leaves it in place.

## What the app does

- **Chart.** The Chart is MapLibre GL over a self-hosted Protomaps (PMTiles) basemap, recoloured from the app's tokens (`web/map/style.ts`, `web/map/chart.ts`). MapLibre and PMTiles load by dynamic import on the first Chart view (`web/map/maplibre.js`). Bases are Night, Chart detail (NOAA ENC display, planning only) and, where a region offers it, Aerial (`baseOptions` in `web/app/LayerRail.tsx`). When you arm waypoint placement on the Chart, a tap that is not checked, is inside a protected area, or is within the 70 m planning margin is refused; placement stays armed so you can choose another position (`web/waypoint-placement.ts`, `web/app/MapStage.tsx`, `web/map/chart.ts`).
- **Terrain, 2D and 3D.** The Chart / 2D / 3D toggle in the map chrome loads `packages/coast` on the first terrain choice, by dynamic import from `web/map/stage.ts` (`web/map/terrain.js`). The Chart and the terrain share one camera. Seafloor relief is nominal, with its survey and datum named in the legend.
- **Layers.** The registry in `web/map/layers.ts` lists them: basemap, aerial, ENC chart, terrain relief, water temperature, swell, protected areas (always drawn), habitat (from zoom 10), shore runs (Shore profile), seafloor, charter grounds, commercial AIS 2024, currents, clouds, marks, the selection and ranked trip spots. Fleet heat, tracks and events are admin only. Each entry shows its basis sentence.
- **Profiles.** Boat, Shore, Spear and Kayak change the default target, depth limit, layers and caveat (`PROFILE_TABLE` in `web/profile.ts`). Kayak uses the boat ranking within a 120 ft screen and reads wind, drift and launch surf first; a forecast cannot clear a paddle. Habitat is described as a place to look; fish presence stays unverified.
- **Language.** The map app's first answer, brief labels and rules cards have English and Spanish copy. A supported `?lang=es` or `?lang=en` choice is remembered on this device; otherwise the stored choice, then the browser's language list (Accept-Language), then English is used. Published port, species and source names and the registry's rule wording stay as published; the rules card labels English rule text (`web/i18n.ts`, `catalog/app/strings.json`, `web/app/RulesCard.tsx`).
- **Brief.** The brief (`web/brief/`) opens with the day verdict (`web/brief/verdict.ts`): Comfortable, Marginal, Rough or Unknown for the morning window (sunrise to noon, or the rest of the daylight once noon has passed) and one sentence naming what limits it, for example "20 kt wind gusting 26 at 10 am." For Boat it is the comfort score's worst hour over the regional forecast (see [the conditions model](conditions-model.md#the-day-verdict)); Shore, Spear and Kayak take their own hourly grade. Then come the wind, swell, water and tide tiles (one row of four in the 300 px desktop column), Details (the readings line, the longer summary, what is missing and the profile's caveat, with a count of missing or stale sources on the summary), where to look and the lower-exposure window. Without a forecast the tiles read unavailable and the verdict Unknown; an old run reads stale with its age. In the map app the Boat verdict is rated for the boat saved on this device, and its basis names that boat; with no saved boat it names the reference 23 ft boat (`web/brief/Brief.tsx`, `web/brief/verdict.ts`; the name and fallback are in `web/boat-range.ts`). The landing page's Boat verdict also reads the saved boat and the Boat comfort limits on this device, and names the saved boat or the reference 23 ft boat when none is readable (`web/landing/live-verdict.ts`, `web/landing/Landing.tsx`).
- **Where to look.** A short list of screened habitat places for the profile: a place to look, not verified fish presence or catch odds (`web/brief/WhereToLook.tsx`). For Boat, a place's distance and range use a computed water route over the land-water screen and read "by water"; where no route is computed, or the route has not finished, the distance is a labelled straight line. One list computes at most 24 routes and a place outside the range is not routed; the rest keep their labelled straight line (`routedPicks` and `ROUTE_BUDGET` in `web/ranking.ts`, the route search in `web/route.ts`). Kayak also uses the water route from its chosen launch, with no run time; while no route is computed it keeps a labelled straight line and says why. Shore and Spear keep the ranking's straight-line picks (`web/brief/WhereToLook.tsx`, `web/launches.ts`).
- **Run time and return window.** For a Boat brief, `web/brief/run.ts` works out the run from the harbor to the chosen place at your own cruise speed, the latest turn-back time to be in by the end of the window, and the fishing time left. The distance is the water route over the NOAA land-water screen and reads "by water"; with no route computed it is a labelled straight line that says why (`web/brief/Run.tsx`, `web/route.ts`). It is a planning distance, not a navigation route, and it leaves out sea state, the bar crossing and fuel. No cruise speed means no run time, and no window means no return time.
- **Entrance timing.** For a Boat brief with a named entrance, the line beside the run shows "Leave by … · be back by …" for the longest daylight stretch that is not Hazardous, with the hours of caution named, or "No bar flag in this window" (`web/brief/Run.tsx`, `packages/coast/src/entrance-window.ts`). When the drivers are missing (no seaward bearing, or tide or swell missing in the window) it reads "Entrance not judged" and shows no times; with no window it says "No window today." These are forecast hours, not observed bar currents or entrance clearance, and they are separate from the turn-back time above.
- **Time dock.** `TimeDock.tsx` scrubs or plays 169 hourly samples (`web/hour.ts`) in the region's time zone. A `?hour=` outside that range is kept and the slider turns off.
- **Conditions.** The view shows the selected hour, a forecast chart, source clocks, tide events and the profile's notes (`web/app/views/Conditions.tsx`). It compares NOAA (GFS, GFS-Wave) with ECMWF (IFS, WAM) (`web/conditions.ts`). Under the tide events it states the moon's phase and lit fraction at local noon of the chosen day in the region's zone (`web/moon.ts`, Meeus, *Astronomical Algorithms* ch. 48); the phase feeds no score or window.
- **History.** Recorded station history, shown only where a local coast report binds the region; elsewhere the view says history is unavailable (`web/app/views/History.tsx`).
- **Fleet.** The charter-grounds layer with dates and a basis sentence (approximate search outlines from published trip records, not AIS-confirmed positions), the Commercial AIS 2024 option (apparent fishing effort is not proof of fishing or catches) where a region has it, and an admin-only part (`web/app/views/Fleet.tsx`).
- **Reports.** Dated catch cards, recent fishing evidence and discussions, and charter evidence, each with its source link. Nothing ranks places or scores a catch (`web/app/views/Reports.tsx`).
- **Limits.** Comfort limits and cruise speed are yours, kept on the device (`web/limits.ts`).
- **Trip plan and GPX.** The trip plan dialog ranks screened reef spots (Best available) or takes the marks you add, re-checks protected areas and the reef publication when you export, and downloads GPX, a share-sheet file or offline notes. The plan is saved per region in this browser. A signed-in person can also press "Alert me for this trip" to save one private snapshot of it with a trip alert: nothing is sent until that press, and the browser draft stays as it is (see Saved-trip alerts). State is `web/planner.ts`, the view `web/app/Planner.tsx`, the dialog `web/app/Trip.tsx` and the wiring `web/trip.ts`, all loaded on first open. When you have chosen two or more stops, the dialog lists them in order as legs, from and back to the home port when one is chosen (otherwise the run from port is not counted). Each leg takes the water route where one is computed and otherwise reads "straight line", and the dialog totals the distance, and the run time when a cruise speed is set; sea state, the bar, fuel and conditions at each stop are left out (`web/app/Planner.tsx`, `web/trip-legs.ts`, `web/route.ts`). Each leg also screens the whole line against protected areas: it shows "Protected areas not checked", "Inside <name>" or the distance from a nearby boundary when applicable; a checked clear leg adds no extra line (`web/trip-legs.ts`, `web/app/Planner.tsx`, `web/waypoint-placement.ts`). These legs are a planning sum shown in the dialog; they are not exported as a navigable route and the dialog does not steer them around protected areas. GPX polygons are separate track rings; they are not navigable routes.
- **Saved-trip alerts.** Signed-in people save a date, area and comfort limits and get material changes and a day-before assessment from saved-trip alerts in the account menu (`web/app/TripAlerts.tsx`, `web/alerts.ts`). They do not certify navigation or entrance clearance. From the trip plan, "Alert me for this trip" saves the checked stops as a private snapshot with the alert (`web/planner.ts`, `web/planner-alerts.ts`, `web/app/Planner.tsx`): the plan's fishing date (today to seven days ahead in the region's zone), the forecast area nearest the first stop (alerts assess that area, not the weather at every stop), the 7–13 hours and comfort limits the alerts form starts from, the plan's target (lingcod and rockfish are saved under the region's Reef group), up to 12 stops (launch included) with their names and positions, and the computed legs as planning estimates, not a navigation route. Private notes are never copied. Nothing is trimmed: a plan with more than 12 stops, a stop inside, near or not checked against protected areas, or an invalid date or leg is refused with the reason. Later edits to the browser plan do not change the saved alert. "Use again" on a saved trip starts a new window from it, copying the area and alert species the region still lists, the hours and the limits, requires a newly chosen date and sends nothing until Save.
- **Account.** Passkey sign-in, the boat profile, comfort feedback and saved trips sit behind the account menu (`web/account.ts`, `web/app/AccountMenu.tsx`). The account panel opened from that menu also holds two private lists (`dist/account.js`): a catch log (`server/routes/catch-log.ts`), where each entry is fish, a blank or not sure, with an optional position that stays private, and saved spots (`server/routes/spots.ts`), up to 100 named positions with an optional private note. A catch-log entry can optionally name one of the owner's saved trips; matching entries show that trip's date in the account list (`dist/account.js`). Past saved-trip details show matching logged outcomes beside comfort reports, separately from forecast assessments; this is the returned catch log, not proof that a trip with no displayed entries was unlogged (`web/alerts.ts`, `web/app/TripAlerts.tsx`). A signed-in person can add a saved spot as a stop in the browser's trip plan; the planner re-checks protected areas before adding it (`web/planner.ts`, `web/app/Planner.tsx`). A signed-in person can also save an eligible selected map mark to these private spots after the current protected-area check; inside, within-70 m and unchecked positions are not saved (`web/saved-spots.ts`, `web/app/MarkCard.tsx`). Neither private list feeds a public feed, public map layer or score (`server/routes/catch-log.ts`, `server/routes/spots.ts`), and an empty list is just empty. A signed-in owner can turn on the off-by-default, Chart-only "Your saved spots" layer in the legend: it reads the owner's spots once per session, draws each as a named pin visible only to that owner, and a pin's card shows the shared protected-area reading and never the private note; the choice and the spots are not kept in the address, a share link, a feed, an export or usage measurement (`web/map/saved-spots.ts`). Notes are never drawn, and the existing GPX and records exports are unchanged. The owner can download saved spots as GPX: that GPX file holds names and positions, never private notes. The whole GPX download is withheld if any spot's protected-area check is unavailable or the screen is older than 36 hours; spots inside or near a protected area are left out of an otherwise successful file. A saved spot outside the current protected-area screen's coverage reads as not checked, not clear, and is not exported. If any selected spot is unchecked, the saved-spots GPX export is refused as a whole; the private spot remains stored (`dist/account.js`, `dist/geo-screen.js`). The owner's **Export my records** privacy download also includes saved spots with their notes and catch-log entries with their coordinates (`web/app/TripAlerts.tsx`, `server/routes/account.ts`). Anonymous map browsing needs no account.

## Data, storage and offline

Shared cloud jobs publish regional environmental evidence. A Worker serves cached public feeds, with direct-provider recovery in the browser for a few live sources. Private records (accounts, saved trips, alerts, comfort feedback, catch-log entries, saved spots) live in D1; public assets contain no credentials or private records. See [production operations](production-operations.md) for isolation and retention. Hosting providers and external map/weather services process ordinary network requests. NOAA ENC chart tiles are fetched only for the visible map.

The service worker `dist/sw.js` precaches the landing page's first paint but none of the map app's files (listed in `/precache.json`, written by `scripts/precache.mjs`); the map app opens offline only after Save for offline. It keeps the latest public data it has seen, and answers from a saved trip pack when the network fails. Anything served from a save is marked `X-SC-Offline: <saved-at>` and the page shows an offline banner; saved data is never shown as live.

The offline pack is saved only when asked (account menu, Save for offline; `web/trip.ts`, `dist/offline-pack.js`, `dist/offline-core.js`). It holds NOAA ENC chart tiles for the selected region at zoom 8–12 (at most 1,500), the app's page and files (about 2.2 MB), and the self-hosted base map's tiles for the region at zoom 8–12 under the same cap, stored as the byte ranges the map reads (95 base-map tiles for Morro Bay; `tests/test_trip.mjs`). Where the region's `chart_files` lists them, it also stores the shoreline, the land-water index and lines (`land-water.json`, `land-water-lines.json`) and the full and overview depth contours, so the land/water screen and the contours can load from the pack; each is requested only when listed, and one that could not be downloaded is counted as missing offline in the Trip dialog, never assumed. Saved files carry their saved time and the same evidence limits as online, and a by-water distance is still a planning distance, not a navigable route. A separate coastal snapshot is handled by `dist/coastal-offline-core.js`. The app is a mobile website; installing it to the home screen is optional (iPhone and iPad need it for push alerts).

The pack's last phase saves the water-temperature and current layers when the region publishes them and they are current (`web/map/ocean-pack.ts`; plan [offline ocean coverage](plans/offline-ocean-coverage.md)), each whole or not at all, and writes what happened to the pack's `ocean` record. The Save for offline dialog reads that record (`web/trip-ocean-lines.ts`) and puts two lines under each saved region, Water temp and Currents. A saved layer reads "saved · not shown after <day and hour> · only for hours on or after the analysis" (water) or "· only for forecast hours" (currents), the last moment the map's readers can still draw it, or "saved · past its age limit" once that time has passed. A layer that was not saved says why: "not saved: failed check", "too large for this pack", "forecast too old to show offline", "no current data at save time" or "not published for this area". Morro Bay and Cambria read "from Coastal readings (saved <time>)" or "(not saved)". Packs saved before this phase show no line. The lines are a record of the save, not a promise: the map's readers still check age and source at display time and decide what is drawn, and saved data is never shown as live.

## Evidence limits

The Morro Bay atlas is a dated research layer, with no AIS-confirmed charter hotspots or verified catch success. It shows official MPA boundaries and screens all fishing geometries against them at load; this is not a complete live closure service. It has no nautical navigation route or harbor-current model. Saved-trip threshold alerts do not certify navigation or entrance clearance. Central Coast qualified targets end at Point Estero; Cambria–San Simeon adds geological context. Southern California adds 410 historical island habitat outlines and 84 source-grid terrain views with explicit datum and coverage limits. The excluded source products remain excluded. Weather/search-reference coverage extends offshore. Search references are constructed samples, not species detections or charted routes.

Forecasts are regional model values, not observations at individual targets. The browser checks units, timestamps, populated fields, published end times, model disagreements, and inconsistent gust/component values. The brief leads with one comfort verdict for the morning window (sunrise to noon, or the rest of the daylight): Comfortable, Marginal, Rough or Unknown, from the worst hour's conditions score, with one sentence naming the charge the score took most for (`web/brief/verdict.ts`, `chargedCosts` in `web/score.ts`). It is never a go/no-go clearance or a qualified trip recommendation. The lower-exposure windows and comfort words come from one disclosed conditions model ([conditions model](conditions-model.md), `web/score.ts`); bite potential stays unknown. The qualitative hourly comfort screen uses disclosed wind/sea preferences and does not calculate transit, verify four fishing hours, or certify an entrance. From the day after tomorrow the outlook is provisional (`packages/coast/src/daily.ts`); the verdict line and the Wind and Swell tiles say so. Active alerts are a retrieval-time snapshot, not future clearance. Provider metadata are not guaranteed run attribution for every value in a rolling timeseries. Stale evidence cannot earn a calmer label.

NOAA chart images follow the service's portrayal units. Wave, tide, and habitat cards use feet; wind uses knots. Wave/wind directions are from; current direction is toward. All timestamps render in Pacific time. NOAA tides are astronomical predictions for Port San Luis, not Morro Bay bar currents. Dated buoy observations come through the public conditions feed. Harbor pages remain external references, not live entrance clearance.

## Hosting

The site is served by SkipperCast's Cloudflare Worker (`wrangler.jsonc`), which publishes the built `dist/client` and `dist/server`; see [Cloudflare](cloudflare.md). Source credentials, generated archives, DNS receipts, and personal monitor state are not committed. Deploys come only from `main` through `.github/workflows/deploy-cloudflare.yml`; a failed deploy is rolled back, never repaired by hand in the dashboard.

The private personal Telegram monitor is not wired into the public web app. The portable Python collector and alert lifecycle stay available for a later authenticated integration.

## Live measurements

Dated NOAA buoy readings, airport weather and measured water level come through the public conditions feed. The brief uses measured buoy seas when fresh and labels a forecast fallback. The brief reuses a loaded regional forecast for up to 30 minutes before it asks again (`FORECAST_MAX_AGE_MS` in `web/brief/Brief.tsx`). Refresh intervals for observations are not verified here; see [Sources and the cloud refresh](live-conditions.md).

## Search and link previews

`dist/landing.html` names `https://skippercast.com/` as its canonical address
and carries WebSite and Organization JSON-LD; Google reads the site name from
WebSite structured data on the home page
([site names](https://developers.google.com/search/docs/appearance/site-names)).
The map stays `noindex`: with no area in the address it replaces itself with the
saved home or the landing, so a crawler would see a redirect. `dist/robots.txt` allows every crawler and names `dist/sitemap.xml`, the
public pages; while the advisor is on, the Worker's robots.txt names that
sitemap and `/sitemap-advisor.xml`. Admin, chat, data and upload pages also stay
`noindex`. Google needs no extra file or markup for its AI features
([AI features](https://developers.google.com/search/docs/appearance/ai-features)),
so there is no `llms.txt`. `tests/test_site_discovery.mjs` checks all of this.

The landing's initial HTML contains Open Graph and X large-image metadata for
`https://skippercast.com/`; crawlers can read it without running JavaScript
(`dist/landing.html`). The app shell also carries a static preview and stays
`noindex` (`dist/app.html`). For an app link naming a validated region, the Worker
rewrites the Open Graph title and description to name that region and, only when
exactly one listed port belongs to it, that port (`server/og.ts`,
`server/routes/assets.ts`). An unknown region leaves the static preview; an
invalid, foreign or repeated port leaves a region-only preview (`server/og.ts`).
Visitor-supplied names, positions, day/hour and conditions never enter those
rewritten fields; the description names kinds of readings, not a current reading
(`server/og.ts`, `server/routes/assets.ts`).

The [published share image](../dist/skippercast-parker-preview.jpg) is a 1736 × 906
JPEG, 493,062 bytes. It preserves the composition and dimensions of the
original generated PNG (from this [prompt](social-preview-prompt.txt)), which is no
longer shipped; recover it from git history if needed. The original 2.3 MB PNG exceeded [Signal Desktop's 1 MiB image download limit](https://github.com/signalapp/Signal-Desktop/blob/main/ts/linkPreviews/linkPreviewFetch.preload.ts),
so Signal displayed the title and description without the boat image. The JPEG
uses a new URL and is less than half that limit. Keep social-preview images below
1,048,576 bytes, publicly accessible as JPEG or PNG, and declared in the initial
HTML. This is separate from ordinary in-app attachment size limits.

The image hash is recorded in `scripts/web-vendor-sha256.json`. Keep image
dimensions, media type and hashes in sync when replacing the card. To check a
change, remove the existing unsent link and paste it into Signal again; an already
sent preview is embedded in its message and is not updated by redeploying the site.

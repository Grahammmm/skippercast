# Add a coastline

For statewide navigation and baseline species, start with the [five-region coastal directory](coastal-directory.md). A coastal browse entry does not satisfy the source requirements of a detailed fishing package. Bind a qualified package to `catalog/coasts.json` when its regional contracts pass. Regional `target_labels` can change display wording without changing biological IDs or legal rules.

A regional package is configuration and evidence, not a fork of the app. The [Southern California rollout](southern-california.md) validates multiple local observation/advisory contexts and a separate jurisdiction in one regional package. Morro Bay–Avila is the working reference; Cambria–San Simeon validates the same map, forecast, jurisdiction and pipeline with a different footprint and geological source.

1. Define a stable region ID and explicit WGS84 extent, timezone, departure harbor, boat/depth preferences, target species and jurisdiction. Offshore tuna samples may extend beyond the bottom-fishing extent. Do not inherit a neighboring port's travel assumptions silently.
2. Run the needs report. Use the discovery skill to identify primary regional providers. Record original dataset footprint, variables, native precision, time coverage, rights and actual access. A station outside the region can be an explicitly labeled reference, not a local measurement.
3. Bind sources in `regions/<id>/region.json`, record regional coverage and the reason for each gap. Use a jurisdiction package for shared rules. Map public assets separately from raw local inputs. Use null for absent datasets; never reuse another region's catch or AIS layer to fill the map.
   Follow the [regulation review pipeline](regulations.md): bind the exact official documents, review every active species and local access notice, and apply a hash-bound decision. Compilation rejects a wrong jurisdiction, missing species or edited legal content without a corresponding review. The regional daily report distinguishes species-rule freshness from area-access checks.
4. Import approved data through a provider adapter. Qualify fishing geometries with the original depth grid, datum, native masks, depth limit and full closure geometry. Keep context polygons separate from qualified targets. Existing legal exclusions remain conservative across every MPA, even where limited species exceptions exist.
5. Compile and inspect the package. Preview status allows explicit geological context and regional forecasts while unavailable targets stay empty. Published fishing targets require ready depth, substrate and MPA coverage, or a hash-validated qualified subset that proves depth/substrate for its exact footprints while keeping the other gates. Partial source coverage remains partial. A production-ready forecast also needs fresh observations, advisories and confidence checks at runtime.
6. Add the region to the existing daily and half-hourly workflow discovery (non-draft packages are discovered automatically). Confirm its first feed receipt before claiming the updater works. No new per-region scheduler or copied app is needed.

The browser loads `regions/index.json`, selects a package with `?region=<id>`, then loads shared components. Region changes reload the page so selection, forecast requests and caches cannot remain attached to the previous region. The default region module is generated from configuration for offline tests and tools. Region identity is checked before consuming feeds or survey windows. Only the legacy Morro Bay feed may omit a region ID.

Selectors are compiled from `catalog/targets.json` and the region's ordered `species` IDs. Each target declares biological evidence IDs, habitat associations and scoring method; local ecological details remain in `catalog/ecology/<profile>.json`. Validation requires a corresponding regulation card (the reef selector expands to lingcod and rockfish). Add a new species through this shared contract, not hardcoded UI branches. A regional `survey_habitat` GeoJSON can publish source-dated context with `fishing_target:false` and `depth_qualified:false`; it never enters target exports, automatic drifts or catch rankings. Optional `map.focus_areas` supply view shortcuts and shareable `&focus=<id>` links without inventing habitat geometry.

The Cambria–San Simeon preview imports [USGS SIM 3327 geology](https://pubs.usgs.gov/sim/3327/), downloaded and checked on September 21, 2026. Its 2015 interpretation is broad context. It does not supply a native grid adequate for this app's 200-foot target qualification or individual-rock imagery. The superficially relevant NOAA H13089 title includes San Simeon, but its published footprint is offshore/south of the intended nearshore expansion; a title alone is not coverage. CSUMB-derived native grids remain withheld where redistribution is unresolved. These gaps are deliberate and visible.

The Cambria preview now binds [NOAA San Simeon station 9412553](https://tidesandcurrents.noaa.gov/noaatidepredictions.html?id=9412553) for high/low predictions. The NOAA API returned populated predictions on September 25, 2026. This is a subordinate station using offsets from Port San Luis, not a direct local current measurement or a Morro Bay entrance forecast.

The Humboldt Bay–Cape Mendocino preview follows the same package contract. Its local references are the Humboldt Bay bar and coastal [NWS marine zones](https://www.weather.gov/marine/ekamz), [NOAA North Spit tide station](https://tidesandcurrents.noaa.gov/ports/ports.html?id=9418767), and [NDBC Eel River buoy](https://www.ndbc.noaa.gov/station_page.php?station=46022). A September 24 source review added [Samoa SMCA](https://wildlife.ca.gov/Conservation/Marine/MPAs/Samoa), [South Humboldt Bay SMRMA](https://wildlife.ca.gov/Conservation/Marine/MPAs/South-Humboldt-Bay), and [South Cape Mendocino SMR and special closures](https://wildlife.ca.gov/Conservation/Marine/MPAs/South-Cape-Mendocino-Sugarloaf-Island-Steamboat-Rock) to the Northern legal watch. All 22 sources were retrieved and hash-bound; this does not clear a specific fishing position or the Humboldt Bay entrance. The region displays 121 dated NOAA H11975/USGS hard-bottom research outlines. They are deliberately non-exportable and **zero** are qualified fishing targets. The first regional daily rehearsal had 67 of 69 sources available; surface current and 46244 swell detail were unavailable or stale, so the feed was degraded rather than silently filled.

Each of those 121 outlines now has an independently [audited distribution of original measured depth cells](../dist/data/h11975-research-outline-original-depths.json), totaling 498,758 eligible cells inside their inset display polygons. The audit reruns the original H11975 BAG and USGS class-3 join with current-source MPA/GEA buffers and historical survey danger exclusions, then rejects changed source counts or hashes. The map shows each outline's observed minimum, maximum and 5th–95th percentile depths; it labels the 2008–2009 survey date and explicitly withholds route, chart and fishing clearance. The statistic is not a continuous depth surface or proof that every point within the polygon is rock. It supplies a tighter evidence queue for subsequent chart, access, date/method and fish-habitat review, without adding waypoints or exports.

The Bodega–Point Reyes preview displays 17 larger historical hard-bottom outlines selected from the [original NOAA/USGS terrain review](../dist/data/bodega-native-hard-terrain-review.json). The review has 74 local outlines: 56 are too small for its terrain ranking, 18 receive only an uncalibrated C habitat grade, and one of those 18 is held near a selected chart-danger feature. Each displayed outline now shows the minimum, maximum and 5th–95th-percentile depths of qualifying measured cells inside that inset outline, directly from its hash-pinned original 2 m NOAA BAG. The statistics describe sampled historical cells, not every location or a safe approach. The outlines retain their source citations and terrain relief but show **no fishing quality grade, fish-presence claim or chartplotter export**. Current chart, approach route, legal date/method and independent species evidence still gate fishing-target promotion.

The [Point Reyes–Pigeon Point preview](point-reyes-pigeon-rollout.md) adds a distinct Pillar Point planning origin, three local forecast samples, 14 bounded CDFW marine-area features and six new official local rule watches. Its first regional daily run received both wind models, both wave models, Pillar Point tide predictions and partial SST, chlorophyll and surface-current grids. Original bathymetry and substrate are discovery leads only, so the package has **zero fishing marks or exports** pending exact-footprint review.

The [Point Arena–northern Sonoma preview](point-arena-bodega-rollout.md) covers the north of the existing Bodega package. It binds separate NWS zones, three forecast samples, two offshore buoy references, 11 CDFW marine-area polygons and six new local legal-source watches. The first 67/67-source run validates the regional collector. A separate original-cell/ENC audit displays 19 dated Fort Ross–Salt Point hard-bottom research outlines from 56 regional historical fragments; **zero fishing marks or exports** are released.

The Point Sal–Point Conception Central preview binds distinct [NWS PZZ645/670 and PZZ673 zones](https://www.weather.gov/marine/loxmz), the [Santa Maria offshore buoy 46011](https://www.ndbc.noaa.gov/station_page.php?station=46011), and distant [Port San Luis tide station 9412110](https://tidesandcurrents.noaa.gov/noaatidepredictions.html?id=9412110). Its four displayed hard-bottom research outlines are the larger pieces of 21 dated original NOAA H11952/H11953–USGS context shapes. None is a fishing target, route, drift or export. A bounded [CDFW geometry snapshot](../dist/regions/point-arguello-conception/protected-areas.geojson) contains Vandenberg and Point Conception state marine reserves. Both are no-take; the local legal watch also holds [Vandenberg's maritime-update page](https://www.vandenberg.spaceforce.mil/About-Us/Environmental/Vandenberg-SFB-Maritime-Updates/) because the scheduled collector received HTTP 403. The official page states Danger Zone 4 is always closed and other vessel safety areas can close during operations. Thus the preview supplies no live access clearance. The current chart, safe approach, original-cell depth distribution and independent fish evidence are still needed before any fishing mark can be promoted.

Their maintained sources live under `skills/`; `python scripts/install_research_skills.py` installs them into the current user's Codex skills folder. Run the system skill validator on the installed copies when available.

Roll back a region by republishing the previous coherent app/package version; mark a problematic new package draft to remove it from discovery. Retain prior feed source times. Do not relabel retained data as a new observation. Existing regions can keep working while one preview is withheld.

Location-aware target menus and nearby rules use the shared [map context contract](local-map-context.md). Configure discovery extents and notice bindings for each new region; do not substitute browsing rectangles for legal boundaries.

Use the [data-quality rollout process](data-quality-rollout.md) for original-survey qualification, dynamic ocean tiles, prospective verification archives and the evidence gates before statewide expansion.

# California coast buildout ledger

SkipperCast now divides the outer coast into the five CDFW ocean browsing regions and **19 smaller discovery sectors**. The sector boundaries are approximate latitude bands for organizing source work. They are not legal lines, navigable areas, fishing grounds or proof of survey coverage. San Francisco Bay and offshore islands need their own local legal/habitat treatment; the existing Southern California package has island focus areas but only a qualified subset of bottom.

`catalog/coastal-sectors.json` is the reviewed sector index. `src/skippercast/platform/sectors.py` verifies that the bands meet without gaps or overlaps and publishes `dist/data/coastal-sectors.json`. A sector records the number of **already published point candidates**, but never calls its whole rectangle mapped. The shared coastal guide can zoom to each sector and shows source-status text. The Northern, Mendocino and San Francisco coast groups still have no detailed regional fishing package; selecting them must not borrow Morro Bay spots or forecast samples. The coastwide Conditions view now requests a fresh model grid near the actual map center for each sector; it is a planning outlook, not a detailed regional trip assessment.

## Survey discovery is running, qualification is separate

The official [NOAA NCEI NOS survey-footprint service](https://gis.ngdc.noaa.gov/arcgis/rest/services/web_mercator/nos_hydro_dynamic/MapServer) provides intersecting surveys with BAG products. `scripts/discover_noaa_surveys.py` queries every sector, validates complete pages, records exact request URLs, retrieval time and response SHA-256, and retains the previous dated result on a failed query. The existing daily workflow runs it when the last **complete** scan is 30 days old, publishes `survey-discovery.json` on the `data` branch and reports degraded coverage. A saved snapshot is a dated fallback. The first complete scan on September 23, 2026 found **183 distinct survey IDs** across the 19 sectors; one survey may intersect several sectors. This is a catalog lead count, not 183 usable high-resolution grids.

To promote one lead, the add-region skill must inspect its original BAG and descriptive report, acquisition date, local footprint and native cells; confirm horizontal/vertical reference, depth, product uncertainty, masks, resolution and rights; then bind any separately verified substrate. The survey compiler checks the full footprint against current MPA/groundfish exclusions and the region's depth allowance. NOAA's survey polygon alone cannot identify rocks, fish or safe passage. [USGS California Seafloor Mapping Program](https://www.usgs.gov/centers/pcmsc/science/california-seafloor-mapping-program) map blocks and groundtruth are a second discovery path, with each product's own terms and scale reviewed. The [NOAA Bathymetric Data Viewer](https://www.ncei.noaa.gov/maps/bathymetry/) is another official access path, not an independent measurement when it serves the same survey.

`scripts/audit_noaa_survey_products.py` checks the original catalog page for every discovered survey, bounds and hashes that response, and identifies direct BAG, descriptive-report and gridded-data links under the same NOAA survey ID. Its first scan found BAG links on all 183 catalog pages and report links on 181. A linked file has **not** been downloaded or qualified by this audit. The existing daily workflow runs the product inventory on a 30-day cycle, retains dated results on a page failure, publishes `survey-products.json`, and reports failures. The coastal guide now lets a reader inspect the dated original product links for a chosen sector. This is a reproducible queue for native-data review, not an automatic point generator.

The first original seafloor-character import is [USGS's Cape Mendocino data release](https://doi.org/10.5066/P9U0SUGL). The source provides a 2 m video-supervised class grid and a separate 2 m bathymetry product. Metadata says class 3 represents hard, rugged seabed, with public-domain redistribution and attribution to USGS and CSU Monterey Bay. The adapter pins the original character ZIP hash and publishes **43 generalized historical context polygons** at a 20 m display grid. It omits patches under 20,000 m², so the outlines must not be treated as exact rock edges. This layer is optional on the Northern guide map and cannot enter waypoint export or fish ranking. The companion bathymetry reports an instantaneous-sea-level reference; it has **not** been used for legal depth qualification. [USGS's Humboldt study](https://pubs.usgs.gov/publication/ofr20241047) reports that the hard, rugose outcrops are concentrated in the southern study area off Cape Mendocino. No current catch or local legal permission follows from that geological finding.

The wider historical USGS/DOI audit now publishes **1,580 MPA-screened generalized hard-bottom context polygons** across four coast groups. Mendocino has no qualifying polygon from that particular set. A separate [CDFW ds3091](https://filelib.wildlife.ca.gov/public/BDB/GIS/BIOS/metadata/ds3091.html) review decoded all 2,870 level-7 tiles over the browse sectors and publishes **712 MPA-screened predicted-hard context polygons** across the five coast groups. This CDFW class is a rugosity prediction with variable original resolution and interpolated shallow gaps, not verified rock. Both layers are optional, context-only and non-exportable. Their displayed edges are generalized, so target promotion must return to the original source cells.

The bounded original NOAA BAG review downloaded and opened **289 of 291** MLLW-named files no larger than 100 MB. Two files lacked a georeferenced overview and are recorded as failures. Of the opened files, 261 passed the strict MLLW/product-uncertainty metadata check; 127 also have a regular overview at 4 m or finer. A 4 m depth/uncertainty screen intersected the generalized USGS and CDFW context separately, producing **42 file-level overlap leads**, not 42 fishable sites. `scripts/summarize_native_sector_leads.py` tests each original BAG geographic bounding box against its sector's actual NOAA discovery request envelope. This excludes associated surveys whose particular BAG lies outside the sector; even an intersecting bounding box is **not** proof that the sector's water was surveyed. `var/native-sector-review-leads.json` records the dated queue and zero-lead sectors. Variable-resolution BAGs require refinement-cell review rather than judging their coarse overview. Original source dates, legal limits, hazard notices and MPA geometry still gate every potential target.

Of those opened products, **59 contain variable-resolution refinements**. Thirty-one have some refinement grids at 4 m or finer (about 108.8 million refinement cells in aggregate). This metadata count says nothing yet about how many cells are in legal fishing depth, pass uncertainty limits, intersect verified substrate, or lie outside closures. It does show why rejecting a VR product based on its coarse overview would throw away potentially useful native detail. The two files without a georeferenced overview require a separate geolocation/metadata diagnosis before their refinements can be used.

The dated, non-target [sector review report](../dist/data/noaa-native-sector-review.json) makes this queue inspectable. The largest regular-grid overlap queues are Arena–Bodega (15 file/sector intersections), Bodega–Reyes (10), Reyes–Pigeon (8), Morro–Point Conception (8), and Point Conception–Ventura (6). A file can appear in adjacent sectors, so these are not additive. This bounded screen found **no regular-grid/substrate overlap lead** for Humboldt–Cape Mendocino, Pigeon Point–Monterey, Monterey–Point Sur, Big Sur, Point Sur–San Simeon or Cambria–Morro. Pigeon Point–Monterey still has one variable-resolution file with some fine refinement cells; those cells have not been depth or substrate screened. A zero means the specific size-bounded NOAA and generalized-substrate intersection failed to produce a lead; it does not mean no rock or fish. The next source pass for those sectors must inspect larger BAGs, variable-resolution refinement cells and local original USGS products before declaring a mapping gap.

### Original-cell Bodega–Bolinas review

`scripts/qualify_regular_bag_hard.py` now intersects **original** 1–2 m NOAA MLLW elevation/uncertainty cells with separately pinned original USGS seafloor-character class-3 pixels for H11732–H11735, H11738, H12109 and H12111. It excludes cells outside 25–200 ft with a 2 m planning margin, cells with product uncertainty over 1 m, two source cells at class edges, 100 m buffers around the complete fresh CDFW MPA and NOAA federal Groundfish Exclusion Area polygon sets, and hazards transcribed from the original NOAA descriptive reports. The NOAA BAG tracking list records pre-edit soundings; the current grid includes hydrographer edits, and the review retains a revision count. The [summary](../dist/data/noaa-native-hard-review-summary.json) publishes source hashes and counts but **no candidate coordinates**. H12111 retains eight review components; H12109 retains none after the same gates. Component counts across adjacent surveys may overlap. This is a reproducible historical substrate/depth screen, not a fishing target or navigation chart.

The [NOAA federal-area feed](../dist/data/noaa-federal-areas.json) now pulls every individual GEA, CCA and YRCA layer from the [NOAA Fisheries WCR GIS service](https://maps.fisheries.noaa.gov/server/rest/services/WCR_SFD_GCA/NOAA_Fisheries_West_Coast_Region_Groundfish_Conservation_Area_service/MapServer) with per-layer count and digest checks. The September 23 collection contains 29 polygons: 10 GEAs, 2 CCAs and 17 YRCAs. Aggregate duplicates and the Cowcod transit corridor are excluded. The coastal browse chart displays the federal areas with a distinct dashed style and a link to each feature's 50 CFR section; it defaults on for reef selection. A daily workflow checks and publishes this feed. The source GIS is approximate and [NOAA says 50 CFR 660 controls the exact legal boundary](https://www.fisheries.noaa.gov/resource/map/groundfish-conservation-areas-maps-and-gis-data-west-coast-region). Only GEAs enter automatic groundfish-candidate exclusion; CCA and YRCA applicability requires additional fishery-specific review. [NOAA's June 23, 2026 action](https://www.fisheries.noaa.gov/action/cordell-bank-area-revisions) replaced the old Cordell Bank groundfish conservation area with a new GEA, which the collector requires explicitly.

The hazard report registry is `catalog/noaa-survey-hazards.json`. The H11732 and H11733 final reports correct some earlier *feet* labels to *fathoms*; the former also says two rocks lack full coverage and their least depths are unknown. The H11734, H11735 and H12111 final HCell notes identify dangers to navigation despite earlier narrative saying none. H12111's final report lists two submerged rocks at 2.00 and 3.22 m. H11738 identifies a rock and a shoal at the edge of multibeam coverage, while its HCell review recommends removing a disproved charted wreck. H12109's assigned historical wrecks were not found under full multibeam coverage and are not treated as habitat. A cross-survey H11733 hold must verify the supporting H11732 report digest. These holds are review exclusions, not safe approach distances; current ENC and notices remain necessary. The San Francisco CDFW rules page was manually reviewed from the official website, but the September 23 automated source refresh failed for all five regional rules pages. This review therefore cannot certify current legal fishing access, fishery-specific CCA/YRCA applicability, other local closures, vessel transit or current fish presence. None of its polygons enters map targets, ranking or export.

## What is ready and what remains

| Coverage | Current state | Next gate |
| --- | --- | --- |
| Statewide browsing | Five coast groups, 19 selectable sectors, regional species candidates and official CDFW links | Local package for each harbor/coast stretch; local menus must be evidence-backed. |
| Protected areas | Statewide CDFW MPA polygons checked by the existing daily source job and shown in the browse map | Screen every new complete target/export geometry against the current authoritative polygon set. |
| Federal groundfish areas | Daily NOAA GEA/CCA/YRCA source feed and distinct coastal-browse overlay; new native review screens current GEAs | Check exact 50 CFR boundaries and method-specific CCA/YRCA applicability before approving local targets. |
| Regulations | Daily source checks for five CDFW ocean pages; reviewed Central and Southern jurisdiction packages | New jurisdiction/notice packages, hash-bound human review for Northern, Mendocino, San Francisco and any Bay/island special rules. No automatic open-season claim from a checked page. |
| Bottom | 132 Central Coast point candidates, 11 survey-qualified Southern island reef patches in partial packages, 1,580 historical USGS hard-bottom and 712 CDFW predicted-hard **context-only** polygons; northern fishing targets remain unpublished | Inspect local native grids/datum and original substrate cells, then qualify depth and exclusions. Never turn all survey leads into spots. |
| Ocean conditions | Every browse sector has on-demand two-model wind/wave morning outlook at the current map center. Three existing detailed packages also have observation/ensemble/surface-water adapters. | Add local buoy/tide/advisory and harbor-entrance contexts, model-run metadata, tested routes and scheduled receipts before a coastwide trip score. |
| Species and methods | Coast-level candidate lists; detailed ecology, rule cards and starter methods in existing regional packages | Add locally supported species dossiers and legal cards per package. Catch probability needs identified catch **and unsuccessful effort**, date, position and independent validation. |
| Charter/commercial activity | Limited sourced activity context in existing mapped areas | Verify vessel identity, archive coverage and loiter methods before publishing any new fleet location. AIS does not prove a catch. |

The rollout unit is a **bounded regional package**, not all California at once. Prioritize a working northern harbor package, then repeat the same gate for adjacent sectors. A preview may expose dated context but must withhold unqualified fishing coordinates, open-season badges and precise bottom images. The site can help a fisherman choose *where to investigate*; it cannot know exactly where a mobile fish is at a chosen future time without fresh observations and a validated species model.

## Reproducible commands

```bash
PYTHONPATH=src python -m skippercast.platform.build
python scripts/discover_noaa_surveys.py --output var/survey-discovery.json --previous dist/data/noaa-survey-discovery.json --max-age-days 30
python scripts/audit_noaa_survey_products.py --discovery var/survey-discovery.json --output var/survey-products.json --previous dist/data/noaa-survey-products.json --max-age-days 30
python scripts/import_usgs_seafloor_character.py --source-id cape-mendocino-character-2023 --archive /local/SeafloorCharacter_OffshoreCapeMendocino.zip --output dist/data/cape-mendocino-seafloor-context.geojson
PYTHONPATH=src python scripts/inspect_noaa_bag_grids.py --inventory var/noaa-bag-head-inventory.json --products dist/data/noaa-survey-products.json --cache var/noaa-native-cache --output var/noaa-native-audit-100mb-refined.json --max-bytes 100000000 --workers 8
PYTHONPATH=src python scripts/assess_native_depth_overlap.py --audit var/noaa-native-audit-100mb-refined.json --output var/native-depth-overlap-leads-100mb.json
python scripts/summarize_native_sector_leads.py --audit var/noaa-native-audit-100mb-refined.json --output var/native-sector-review-leads.json
python scripts/collect_noaa_groundfish_areas.py --output var/noaa-federal-areas.json --previous dist/data/noaa-federal-areas.json
PYTHONPATH=src python scripts/qualify_regular_bag_hard.py --survey-id H11735 --bag-filename H11735_MB_2m_MLLW_2of3.bag --usgs-block OffshoreTomalesPoint --usgs-block OffshorePointReyes --output var/review-h11735-native-hard.geojson
python scripts/summarize_native_hard_reviews.py var/review-h1173{2,3,4,5,8}-native-hard.geojson var/review-h12109-native-hard.geojson var/review-h12111-native-hard.geojson --output dist/data/noaa-native-hard-review-summary.json
PYTHONPATH=src python -m skippercast.platform needs --region <new-package-id>
python scripts/build_primary_strategies.py
python scripts/check_web.py
python scripts/check_repository.py
```

Use `$skippercast-discover-data` to resolve each sector's needs, `$skippercast-ingest-data` to import approved local products, and `$skippercast-add-region` to compile, test and release the package. The established daily and 30-minute workflows discover non-draft packages automatically. Their source and publication health must be checked before claiming the new area updates reliably.

# Regional intelligence release

User-requested features: 2, 3, 4, 7, 8, 9, 13, 14, 15, 18, 19 and 20 from the September 21 product review.

The shared browser components consume versioned regional products. Provider adapters own parsing; regional configuration selects sources, stations and ecological applicability. Scheduled jobs publish normalized data and health atomically. Optional product failure cannot break the map or relax legal gates.

Implementation ledger (updated before release):

| Feature | Shared component / process | Validation |
|---|---|---|
| 2 | Hourly comparison matrix, one UTC forecast clock | Unit/time alignment and missingness |
| 3 | Separate trip-date and source-freshness clocks, method rules | Season boundaries and method gates |
| 4 | Evidence cards: measured, inferred, unverified | Source identity and escaping |
| 7 | Immutable pre-valid-time forecast archive and station verification | No look-ahead, lead buckets, unique runs |
| 8 | Observed spectra, wave encounter explanation, personal comfort feedback | Spectral units/QC; no invented vessel dynamics |
| 9 | HFR and WCOFS adapters | Local masks, vector conventions, actual horizon |
| 13 | iNavX selection, GPX and import wizard | Geometry/MPA gates, names and round-trip parsing |
| 14 | Survey rotation, section and depth band | Native gaps, scales and datum |
| 15 | Regional ecological evidence and method profiles | Primary citations, scope and life stage |
| 18 | Actual ensemble members / published probability fields | Member counts, thresholds, nulls and run times |
| 19 | Private saved-trip alerts and durable outbox | Ownership, opt-in, stable IDs, receipts |
| 20 | Release checks, isolated failures, caching and rollback | Failure fixtures, regional tests, API security |

Public scores remain conditions heuristics. Historical forecast statistics need accumulated observations. Ecological support and vessel activity do not establish a calibrated catch probability.

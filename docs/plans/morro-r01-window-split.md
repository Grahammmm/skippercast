## R2. Offline 2 m estimate versus the actual historical window

`catalog/reaches.json:1319–1351` provides EPSG:3310 bounds of a **line**; `catalog/seafloor-scope.json:14–22` calls it a planning spine, not a habitat footprint. From those committed bounds, rounded for display:

- Width: −91,991.246904 − (−98,313.556654) = 6,322.309750 m. Height: −275,322.923865 − (−282,607.664157) = 7,284.740293 m.
- Divide each span by 2 m and round to the nearest pixel: **3,161 × 3,642 = 11,512,362** pixels. Adding the 255 m buffer on both sides of both spans for illustration: **3,416 × 3,897 = 13,312,152** pixels. Both planning estimates are below 20 and 25 million; neither is the runtime window.
- The actual calculation takes the selected Tier 1 cell union for the source, intersects it with source geometry, buffers by 255 m, rounds on the projected raster grid, and clips to the raster extent (`habitat.py:53–65`). The spine alone cannot reproduce those inputs: `grid.py:166–169,231–241` puts the cell artifact outside the reach catalog, and the run archive locates the reach cell/support outputs under ignored `var/seafloor/` (`docs/archive/seafloor-tiled-habitat-2026-09-30.md:59–61,73–78`). `git ls-tree -r --name-only origin/main -- var/seafloor/reference var/seafloor/reaches/morro-bay-r01` returns no files.

The checked-in run receipt records **26,219,430** Point Estero pixels: **6,219,430** over the rough tiling threshold and **1,219,430** over the classified ceilings if compared numerically. The latter are tested on different windows, not this one. In the rough path the 2 m halo is `round(100/2) = 50` pixels per side, so a full padded read is `(1,024 + 2 × 50)² = 1,263,376`, below the per-read limit (`habitat_tiles.py:27–28,103–125`). That matches the largest reported read across 20 tiles. The receipt is historical, not an exact geometry reconstruction or a new raster read, and it reports zero public polygons **for that run** (`docs/archive/seafloor-tiled-habitat-2026-09-30.md:29–48`).

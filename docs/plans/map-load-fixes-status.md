# Map-load fixes: what landed and what to do next

- **Recommendation:** Take Reports off the ordinary `/map` startup path first. It is still imported before anyone opens it (`web/app/Desktop.tsx:35,75`, `web/app/Mobile.tsx:46,253`).
- **What landed:** Cheaper Aerial tiles, versioned caching, and the two main time-dock CPU fixes are in the code. The map’s startup files are nevertheless 39,104 gzip bytes larger than the November baseline (sections 1–2).
- **Checked on:** `origin/main` at `7335068efd2627dd2a0ba9bea39f09e86a8f252d`, offline build `162ab90fec`. Current phone timings and live cache behavior: **UNVERIFIED**.

## 3. Three next units, ranked by the issue’s measured cold-map cost

The ranking uses separate costs visible in [the issue’s §2.3 waterfall and §3 experiment][baseline], not added savings. In particular, the old basemap interval is elapsed time, not a promised saving; the old library delay was already addressed in part. M4’s 277 KB duplicate was measured on the old path (today’s count **UNVERIFIED**). The overlay size in M6/MB3 is real baseline payload, but the issue gives no comparable cold-map time for that later zoom/overlay work. The issue's Aerial gain is an estimate using a stand-in, not a measured upstream win. The units below are independent; times are **UNVERIFIED effort estimates**, not runtime gains.

1. **MB1 — prove one archive-to-tile read offline (105 minutes; owner sign-off retained).** The old trace spends about **1.06 s** from the first archive header read (8,066 ms) to the first tile range (9,125 ms), including other work in that interval. Start with `server/basemap-tile.ts` (new) and `tests/test_basemap_tile.mjs` (new), using `tests/fixtures/basemap/tiny.pmtiles`. Build a standalone helper using the existing PMTiles dependency (`package.json:24`) and an injected range reader. Given one content-named archive and valid tile coordinates, return its vector tile bytes and a cache identity bound to archive name plus coordinates, not app build; refuse invalid coordinates and mutable names (`server/feeds.ts:165–169,218`). **One test:** read a known nonempty fixture tile and assert its decoded content matches the fixture, its key changes with archive identity, and invalid input does not call the reader. No route registration, live reads, cache deployment or publishing. Owner sign-off is required for the tile-delivery change; first-tile improvement is **UNVERIFIED**.
2. **R4 — load Reports only when opened (100 minutes).** The old first-render task was **684 ms**; the Reports share of that task is **UNVERIFIED**. Edit `web/app/Desktop.tsx`, `web/app/Mobile.tsx` and a new shared `web/app/views/LazyReports.tsx`. Replace the two static imports with a shared on-demand import for the Reports branch only; retain the current page container, heading/focus behavior, direct `view=reports` and error guard. Leave Reports content, styles and the first verdict alone. **One test:** extend the Reports journey in `e2e/v2-shell.spec.ts:59–68` on the existing offline fixture to assert the built Reports module isn't requested on Coast and is requested once when Reports opens and its heading is visible, on phone and desktop. This is the recommended first change because it removes work from the path rather than competing for bandwidth with the first verdict (`web/app/main.tsx:49–55`).

Startup benefit **UNVERIFIED** until a matched fixture waterfall confirms the worker is reused and Chart idle improves without delaying the verdict.

## R3. What to investigate first

**Hidden network, ranked by estimated upper impact while the relevant surface/feature is active.** Cadences are configured intent, not measured background rates. These cases are not all active together. Cache/coalescing, network failure and browser throttling can reduce delivery; the ranking does not assert bytes, battery use or provider load.

| Rank (estimate) | Hidden work and why |
| --- | --- |
| 1 · high per refresh, conditional | **Standalone viewer** can validate habitat heads, read habitat and context, and read `/api/ocean` at a nominal 60 s. Changed matching full-context data can incur a much larger verified asset read (`packages/coast/src/coast3d/viewer.ts:24,78,247–253,295–299`; `packages/coast/src/map/habitat-lifecycle.ts:35–55`). Hosted 3D skips these interval bodies hidden. **Enabled seafloor** is bursty rather than a permanent minute poll: gate/ledger/header/tiles on re-admission, retry fast at first or recheck at expiry (`web/map/seafloor.ts:48,151,391–449`). |
| 2 · frequent checks | **Where to Look** and **drawn ranked trip** can read uncached manifests every 60 s; Where to Look can also check habitat and reload a changed release (`web/brief/WhereToLook.tsx:295–302`, `web/ranking.ts:255–257,299–325`, `web/trip-runtime.ts:267–279`, `dist/seafloor-data.js:38–43`). Keep local stale withdrawals distinct from reads. **Admin health** sends one small endpoint request per eligible minute by source structure, potentially even when signed out (`web/admin/app.tsx:54,63–81`, `web/admin/api.ts:175–178`). |
| 3 · lower frequency, possibly heavier payload | Enabled **Swell/Wind** can read their forecasts at about 30 min; **SST/contrast/fronts/chlorophyll/regional currents** can read a feed and, for tiled products, payload tiles on expiry/hour clocks when their source gates allow (R1 timeout rows; `web/map/forecast-grid.ts:105–116`, `web/map/habitat-feed.ts:321–467`). **CoastReport**, if instantiated, checks every 10 min (managed can no-op by panel visibility or binding; possibly history, `packages/coast/src/coast3d/report.ts:44,52,58–65,79,93,100`). |
| 4 · conditional/short-lived | **Saved spots** usually just recalculates the card: only a missing/failed screen can cause reads, and an in-flight same-region screen is shared (`web/map/saved-spots.ts:303–319,335–349`, `web/trip.ts:89–105`, `dist/protected-areas.js:114–122`). **Forecast skill** has one delayed retry, not a poll (`web/brief/skill.ts:67–89`). Event-batched sends and camera movement debounces are separate single shots (R1), not background pollers. |

**Reduced-motion gaps, ranked separately (estimate):**

1. **Wind preview particles:** continuous canvas movement, the clearest purely decorative gap. Work can run each delivered frame, per particle, until stop. Hidden check avoids the particle computation but not the requeue/clear (`web/map/wind-layer.js:49–76`).
2. **3D viewer damping:** continuous render and projection have the higher likely per-frame compute cost; the motion concern is camera inertia after input, not static rendering itself. No preference check before enabling damping or on frame (`packages/coast/src/coast3d/viewer.ts:64,308–310`). Do not shut off the scene just because reduced motion is set. Chart flyover checks only at start (R2); the finite mobile scroll hold is layout correction, not a decorative loop.

## R4. Smallest follow-up (proposal only)

**One unit, estimated 75–105 min:** add an injectable `startVisibleInterval` in **proposed** `web/visible-interval.ts` and apply it only to the admin `App` health effect in `web/admin/app.tsx:63–82`. Use the cancel/re-arm pattern already in `createClouds` (`web/map/clouds.ts:186–203`): preserve the first visible refresh, do not schedule/start one hidden, clear on hide, refresh once on return then re-arm the existing 60 s, and remove the listener/interval on unmount. Do not alter the startup fleet probe or abort in-flight work as part of this unit. Start with admin because its interval is a self-contained read, not expiry authority. Do not starve route/selection/publication expiry checks by mass-replacing timers (`web/planner.ts:625–657`, `web/coast-data.ts:171–202`, R1–R3).

Proposed offline test file **`tests/test_visible_interval.mjs`**, run `node --test tests/test_visible_interval.mjs` with a fake document/clock and counted callback: initially hidden = zero starts, visible = one immediate plus scheduled ticks, hidden again = no interval or new calls, restore = one re-arm, cleanup = no late work. No endpoint calls in the test. A wind motion check belongs locally where `draw` is scheduled (`web/map/wind-layer.js:49–76`); use the current-layer `matchMedia`/change and still-image pattern as the reference (`web/map/currents.ts:212–214,248–263,301–304`), not a combined visibility/motion rewrite. No motion unit or code change is proposed for this branch.

## R1. Every Worker environment name

- **Env** gives the declaration line in `server/env.ts`; all entries are optional. The per-request `Variables` interface (`server/env.ts:94–108`), build defines, runtime globals (e.g. `caches`), cron triggers (`wrangler.jsonc:50`), and CI-only inputs are not Worker environment properties.
- **Wrangler** gives base-file declarations. **Deploy** gives inputs and the source that maps them into the Worker. `W` = `.github/workflows/deploy-cloudflare.yml`; `S` = `scripts/cloudflare_deploy.sh`; `G` = `scripts/wrangler_config.mjs`. The workflow calls the deploy script at `W:404`, which generates config at `S:117` and deploys it at `S:153`. Generated advisor vars require `ENABLE_ADVISOR` and a nonblank input (`G:94–101,161–165,183–189`); fleet and coast vars require only a nonblank input (`G:107–127,191–192`). Secret inputs are uploaded only if provided (`S:156–203`), not simply because they appear in the workflow. `EXTRA_ORIGINS` is a repository var uploaded through the Worker secret path, despite being grouped with vars in `Env`. `CLOUDFLARE_ACCOUNT_ID` also serves the deploy itself (`W:212`); Worker upload has a separate condition (`S:198–199`).
- **Docs** gives representative positive anchors, prioritizing `docs/cloudflare.md` and the operations runbooks; a plan can describe intended wiring rather than prove it. **Reads** counts source occurrences, not runtime invocations. Each entry gives the overall count and each direct reader's first line and count in parentheses. A keyed limiter lookup is counted once per possible binding; its route selectors are listed separately, not counted twice. Callers that only forward an `Env` object or a resolved value are not reads.

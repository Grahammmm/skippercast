## R1. Each numbered implementation step

1. **Landed — ocean-key detection and offline manifest selection.** The pack helper and the classic worker recognize the same same-origin manifest and tile paths; the worker has its own identical predicate because it cannot import the module (`dist/offline-core.js:88–95`, `dist/sw.js:3–7,51–57`; parity test `tests/test_sw.mjs:470–487`). On a network failure, the worker ignores unfinished packs and prefers the committed pack's manifest unless the recent-data copy is newer and has every layer the pack can serve. It checks tile presence, not hashes or ages; other requests (including tile URLs) retain newest-saved selection (`dist/sw.js:144–169,174–221,239–254`; cases in `tests/test_sw.mjs:490–541,665–679`). This implements plan step 1 (`docs/plans/offline-ocean-coverage.md:598–601`).
2. **Landed — pack integration, ocean phase and metadata.** Both the file list and the copy from recent browsing skip ocean keys; the latter skips them before even reading the response (`dist/offline-pack.js:68–86,118–134`). The explicit save calls `v2Pack`, whose last phase uses the same report binding as the layers to choose either a read-only Coastal readings pointer or the regional download; a regional 404 becomes `path: none` (`web/trip-runtime.ts:126–145,186–200,276–284`). The regional downloader checks the size and remaining drawable time before fetching tiles, rejects offline copies, reuses the readers' manifest and tile validation, and buffers each whole layer before writing. It stores the exact checked manifest last and records its size and hash (`web/map/ocean-pack.ts:11–20,73–104,107–141,145–216`; `web/map/habitat-feed.ts:115–130,172–194`). A refused tile can leave the other layer saved; a storage write failure or cancel discards the candidate and leaves the previous committed pack alone (`web/map/ocean-pack.ts:148–153,184–213`, `dist/offline-pack.js:144–169`, `tests/test_trip.mjs:365–401`). The top-level `ocean` record is additive under pack schema 1 and its payload is counted once (`dist/offline-pack.js:144–157`, `web/trip.ts:165–175`, `tests/test_trip.mjs:287–308`). This implements plan step 2 (`docs/plans/offline-ocean-coverage.md:602–609`).
3. **Landed — Trip coverage lines and copy.** The dialog shows separate Water temp and Currents lines from the pack record. It reports the deadline and hour restriction, age-limit or failure reason, or the Coastal readings status as recorded at pack save; an older pack with no ocean record shows no lines. The old “not prefetched” sentence is replaced, and the web-app guide describes the new behavior (`web/app/Trip.tsx:167–184`, `web/trip-ocean-lines.ts:19–48`, `web/strings.en.generated.json:1604,1656–1671`, `docs/web-app.md:139`; examples in `tests/test_trip.mjs:404–455`). This implements plan step 3 (`docs/plans/offline-ocean-coverage.md:610–612`).

The three implementation steps are landed; that does not mean every proposed test is in place or that data saved today will still draw tomorrow (R3; `docs/web-app.md:139`). The original plan's “today” text about an unfiltered copy and a GitHub habitat download (`docs/plans/offline-ocean-coverage.md:10–28,96–98`) is historical: the active region rewrites that feed to a same-origin URL, then the files phase excludes it (`dist/region.js:3–6,25–29`, `dist/feeds.js:5–22`, `dist/offline-pack.js:119–125`).

## R2. What a new Morro Bay pack tries to save

This is the explicit save list plus eligible recent responses, not a guarantee that every optional request succeeds. A missing region config or required app file fails the save rather than replacing an older pack with an unopenable one (`dist/offline-pack.js:101–134,150–169`, `web/trip-runtime.ts:167–185`).

| File family | What's in scope for the chart pack |
| --- | --- |
| Region and shared files | Region directory, config, manifest, coverage, strategies and regional intelligence; configured atlas, habitat index, protected areas, regulations, charter grounds, AIS layers/evidence, daily evidence, bottom index, ecology and search plans; shared coasts, home ports, species evidence and central coverage ledger (`dist/offline-core.js:109–131`, `regions/morro-bay/region.json:486–499`). The bottom index entry is not a recursive download of its members. |
| Conditions and public feeds | Daily and conditions feeds and regional intelligence feed; region-specific forecast and intelligence API bundles; daily regulations, MPA boundaries, additional closures and brief. Conditions adds wind/wave models and their metadata, tide predictions and NWS marine alerts. The v2 phase also saves predictions for a selected non-default tide station, if any (`regions/morro-bay/region.json:500–501,564–565`, `dist/offline-core.js:97–127`, `dist/offline-pack.js:31–43,119–125`, `web/tide-selection.ts:90–98`, `web/trip-runtime.ts:178–179`). |
| Recent public responses | Eligible `sc-data` responses from this page session, skipping existing pack entries and same-origin regional habitat manifests and tiles. Recent ocean responses can still answer from `sc-data` itself; that cache is limited to 150 entries and is not the pack (`dist/offline-pack.js:68–86,128–134`, `dist/sw.js:29–31,217–225,239–254`). |
| NOAA ENC chart | WMS chart images for the selected chart layer set, under stable tile keys; 95 planned in Morro Bay at map zooms 8–12, under the 1,500 cap (`dist/offline-pack.js:135–143`, `dist/offline-core.js:4–14,17–23,33–54`, `tests/test_trip.mjs:50–59`). |
| v2 app and chart side files | `/map`, app assets and versioned glyphs from the build list, basemap manifest, published full and overview shoreline and depth contours, land-water index and lines, atlas-marks and search-plan startup index. The poster is not on this save list (`web/trip-runtime.ts:107–124,167–185`, `scripts/precache.mjs:106–117`, `web/startup-forms.ts:8–10`, `dist/regions/morro-bay/region.json:1`). |
| v2 basemap | PMTiles byte ranges needed by the reader, not a whole archive; 95 tile positions planned at archive zooms 7–11 (map zooms 8–12) (`web/trip-runtime.ts:85–104,186–200`, `dist/sw.js:48–50,106–110,389–396`, `tests/test_trip.mjs:50–70`). |
| Ocean and seafloor | No same-origin habitat manifest, SST or WCOFS tiles in a new Morro Bay pack, even if browsed; only the ocean metadata and any Coastal readings saved-at pointer. Seafloor habitat tiles are not cached, so their worker expiry gate is not bypassed (`tests/test_trip.mjs:321–345`, `web/trip-runtime.ts:131–138`, `dist/sw.js:60–77`). |

**What won't draw with only the pack:** Morro Bay's center binds Estero Bay's coastal report (`regions/morro-bay/region.json:27–31,76–86`, `packages/coast/src/state/report-binding.ts:7–22`, `web/map/currents.ts:162–168`). Water temp uses `/api/coast/report`; Currents uses `/api/coast/ocean` for both WCOFS and any available HF radar. A failed coastal read does not switch either layer to regional tiles; offline with no usable snapshot they show “not saved for offline.” Save Coastal readings separately: it commits report, ocean and history together, and the worker only falls back to a complete, validated snapshot. Even then, the layers still check age, the requested hour and whether the grid can be drawn (`web/coast-data.ts:3–5`, `web/map/sst.ts:143–155,177–187,334–352`, `web/map/currents.ts:100–109,129–145,306–324`, `dist/coastal-offline-core.js:2–7,24–32`, `dist/sw.js:273–289`).

**Other overlays:** Temp contrast reads the regional SST files even in Morro Bay, so the chart pack alone does not supply it. The v2 Chlorophyll reader also uses the regional feed, but chlorophyll is not one of the two layers the ocean phase saves. A matching recent cached copy can still work if it passes the respective reader's checks. Seafloor habitat is also unavailable from the pack; don't confuse it with the separately saved chart contours (`web/map/contrast.ts:145–163,237–247`, `web/map/habitat-feed.ts:406–422`, `web/map/chlorophyll.ts:26–33,69–88`, `web/map/ocean-pack.ts:11–20`, `dist/sw.js:74–77,239–254`, `web/trip-runtime.ts:115–119`).

## R3. Next unit (estimate: 90 minutes, tests only)

**Prove that a saved SST layer still draws when the recent manifest is newer but incomplete.** Take the read-side slice of plan test 12 (`docs/plans/offline-ocean-coverage.md:549–555`). The existing pack fixture calls the real save but omits SST; the worker fixture checks which manifest wins without calling the layer readers. Keep those suites and close the gap at the worker-to-reader boundary (`tests/test_trip.mjs:219–224,287–308`, `tests/test_sw.mjs:441–524`, `tests/test_habitat_feed.mjs:60–74`).

- **Files:** add the case to `tests/test_sw.mjs`, using its `loadWorker`, `dispatch`, `commit` and `keep` fixtures. Extract the existing 6×4 SST grid fixture from `tests/test_habitat_feed.mjs:22–48` into `tests/helpers/sst-feed.mjs` and reuse it in both tests; use the existing WCOFS helper (`tests/helpers/wcofs-feed.mjs:13`) as-is. No runtime edits or browser required.
- **Focused test:** seed a committed synthetic pack with a valid fresh SST grid and a manifest that also lists eligible WCOFS with no saved WCOFS bodies. Use the cache fake's `put` with the original SST bytes so the reader's hash check still matters (`tests/test_sw.mjs:14–24`, `web/map/habitat-feed.ts:172–194`). Let the real worker see a newer manifest with distinct SST tile keys online, but no tiles. Then throw on network requests and use `dispatch` as the real readers' fetch adapter. At a supported hour on the injected clock, assert the SST status supplies a drawable grid and that the served manifest carries the pack's `X-SC-Offline` stamp; Currents must have no drawing and report `TILES_NOT_SAVED`. If the worker goes back to newest-wins, the SST read must fail because none of the new tile keys is present (`dist/sw.js:201–221,239–254`, `web/map/sst.ts:164–191`, `web/map/currents.ts:112–126`). Run `node --test tests/test_sw.mjs tests/test_habitat_feed.mjs`. This tests saved bytes through the real readers, not a new writer or a live offline trip.

**Owner decisions, not blockers for the test:** Step 2 already uses a 12,000,000 B total, a 1 MiB manifest limit, at most 64 tiles per layer, 5,000,000 B per tile and a 60-minute minimum remaining window (`web/map/ocean-pack.ts:13–20,107–141,166–190`). A per-region cap, an opt-out based on pack share, a quota retry, or a different minimum window need separate decisions before changing those defaults. Longer WCOFS life would need a separate decision on data refresh or the reader's six-hour retrieval gate (`docs/plans/offline-ocean-coverage.md:618–644`). Background prefetch or automatic refresh is outside all three steps and would need explicit owner approval; the shipped save runs only on request (`docs/plans/offline-ocean-coverage.md:122–131,614–616`, `web/trip-runtime.ts:276–284`).

## R4. Byte impact (payload estimates, not device measurements)

| Case | Basis and estimate |
| --- | --- |
| Morro Bay, as shipped | **0 B** for the regional ocean payload (`ocean.bytes`); the small metadata record is separate from these body counts. Coastal readings can use up to **32 MiB separately**, not added to the chart pack: 8 MiB report + 8 MiB ocean + 16 MiB history (`web/trip-runtime.ts:131–138`, `dist/offline-pack.js:144–157`, `dist/coastal-offline-core.js:2–7`). |
| Morro Bay, if it used the regional path (it doesn't) | Historical plan example: 46,763 B manifest + 17,130 B SST + 626,020 B WCOFS = **689,913 B**. The pinned main tree's static examples instead total **1,017,545 B** (54,509 + 333,733 + 629,303 B; commands below). Neither number is added to a Morro Bay chart pack. |
| Southern California, regional example | 55,880 B manifest + 101,030 B SST + 4,154,326 B WCOFS = **4,311,236 B** if both are eligible; **156,910 B** with just SST and the manifest, or **55,880 B** with just this manifest. These and the historical Morro Bay estimate use the plan's 2026-10-20 inputs, not today's feed. WCOFS had about 1 h 13 min left at generation in the Southern California example; a later save might skip it rather than add those bytes (`docs/plans/offline-ocean-coverage.md:44–76`, `web/map/ocean-pack.ts:133–141,164–216`). |

To reproduce the static tree counts from the snapshot, take the size column from `git ls-tree -lr c26ef040374f33159ffa978820785006733981d4 -- dist/regions/morro-bay/habitat-dynamics.json dist/regions/morro-bay/habitat-tiles/` and sum by current layer filename prefix (eight SST and eight WCOFS blobs). These are committed examples, not the `/feeds/conditions/` responses used at save time (`web/map/habitat-feed.ts:70–74`, `web/map/ocean-pack.ts:145–158`). The plan also estimates about 2.2 MB of app files; neither that estimate nor the 95 planned chart and basemap positions measures the total pack. Actual tile/range sizes, feed responses, optional files and the recent session vary, and `meta.bytes` counts response bodies rather than device storage overhead (`docs/plans/offline-ocean-coverage.md:629–633`, `tests/test_trip.mjs:50–59,300–307`, `dist/offline-pack.js:101–134,144–157`, `web/trip-runtime.ts:85–104,178–200`).

# Why the seafloor manifests go unavailable

**Finding:** Seafloor’s `prepare` job marks the selected regions unavailable before it refreshes screening or starts the long rebuild (`src/skippercast/seafloor/jobs.py:347–365`).
**Timing:** Pushes can start the same job as the daily schedule; the issue and run records below show both, including failures followed by a later rebuild.
**Recommendation:** After screening confirms that nothing relevant changed, put the still-valid release back online during the rebuild; keep the safety hold for changed inputs or failed checks (section 3).

## 2. Who writes the bad state

- **Before the build:** The `prepare` job puts `{"status":"updating"}` at the public manifest URL for every region selected by that run, then refreshes the restriction data. If refresh raises, it writes `held` with reason `screen-refresh-failed`. This deliberately hides habitat until it can be screened again, while still allowing the physical survey work to proceed (`.github/workflows/seafloor.yml:69–90,94–121`; `src/skippercast/seafloor/jobs.py:347–365`). If the reach batch is incomplete or the build fails, `finish` can skip or fail upload without restoring the preceding release (`jobs.py:508–549`). A subsequent run can then be the one that restores it.
- **During the final switch:** The `publish` job builds the bundle, then `publish_bundle` normally puts `updating` again before replacing the stable archive and verifying the export and archive. It puts the finished manifest only after verification; a failed read-back leaves the hold. There is already a narrower, no-hold path for adding just the slim reef file when the served fields match (`.github/workflows/seafloor.yml:123–132,157–175`; `jobs.py:538–548`; `src/skippercast/seafloor/publish.py:422–467,479–482`). The finished manifest is `held` if no habitat qualified. A `ready` bundle already expired at upload is rejected; a previously ready manifest can age out without a new write. Expiry follows the oldest relevant screening date plus 35 days, not the cron time (`publish.py:203–214,297–318,397–399`). `src/skippercast/seafloor/manifest.py:10–16` loads a survey inventory; the public control writer is not in that file.

The browser fetches the manifest without cache, rejects `updating`, `held`, expiry, a wrong region or an incomplete archive hash, and hides the layer when the check fails (`dist/seafloor-data.js:24–52`; `web/map/chart.ts:274`; `web/map/seafloor.ts:392–429`). An already open map can retain previously drawn features until it rechecks, expires the manifest, or needs new data; it does not necessarily blank when the issue opens (`web/map/seafloor.ts:404–429,434–451,503–514`). ## 3. Smallest fix

**Shorten the hold without weakening the screening gate.** Keep the initial `updating` hold during restriction refresh and keep the failure path fail-closed. In `src/skippercast/seafloor/jobs.py`, save the prior ready control before the hold; after a successful refresh, restore it only when it is still unexpired and a saved release binding proves the same inputs remain cleared. Start conservatively: require the same main commit and matching screened scope, policy and checked layer hashes, with `load_snapshot` still returning ready for the prior release’s reaches. Treat missing evidence, a changed commit or screen, a failed refresh or expiry as a hold. Do not extend the old expiry. Use a conditional object write so the restore cannot replace a manifest another publisher wrote in the meantime (`jobs.py:347–365`; `src/skippercast/seafloor/screen.py:61–112`; `src/skippercast/seafloor/publish.py:363–373,426–434`). This deliberately starts with repeat builds of the same code/data inputs; it is not a promise to eliminate holds on every push.

In `src/skippercast/seafloor/publish.py`, stamp that binding on new releases and keep the hold immediately before changing any stable public data: move the existing hold to before the regional sync, which can already write the export. Keep checksum read-back and the final manifest write last. Leaving the old manifest up while overwriting the same archive or export key would still cause 503s on a hash mismatch (`publish.py:419–467`; `scripts/publish_r2.py:281–289`; `server/feeds.ts:329–359`). Keep the existing documented screening and interrupted-switch safeguards (`docs/seafloor.md:716–730`); any change to when retained data is allowed should be agreed with the owner. No workflow or schedule change is proposed; any such change **needs the owner's word**.

**One focused offline test:** In `tests/gis/test_seafloor_publish.py`, extend the fake-bucket prepare test (lines 270–287) into one parameterized continuity case. Seed a prior ready manifest; with a delayed rebuild, assert the exact old bytes and expiry are restored after a successful unchanged screen. With changed or failed screening, expired or missing proof, or a concurrent control write, assert the old ready manifest is not restored. Keep the existing checksum-before-ready and corrupt-read-back tests (lines 141–164) unchanged. Estimated under two hours for this narrow first pass; **UNVERIFIED** until implemented. It does not fix gaps that require a new screening decision or an immutable archive cutover.

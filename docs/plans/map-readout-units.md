# Make Chart readouts and legends follow the units choice

- The Chart prints fixed units on taps, wind labels and scale keys even though Settings offers display choices (`web/app/UnitChoice.tsx:12–26`, `web/map/wind.ts:75`, `web/app/Legend.tsx:208,268`).
- **Recommendation:** Convert the numbers and their unit labels together, just before display. Keep the samples, colour cutoffs and exports as they are (`web/units.ts:3–10`, `web/map/swell.ts:381`, `web/unit-choice.ts:1`).
- Checked against staged `origin/main` at `bcaeee0947f8fd2c68c2b6324f17550c1d47b020` (source checks in Section 4). This is a design, not a browser or live-site measurement.

## 2. Where conversion belongs (C2)

**Use one small display helper, called where the text is made.** Proposed inputs: a finite canonical value, its quantity (height, speed, absolute temperature, temperature difference, or rate), the selected units, locale and precision. Return text, not a changed sample. Reuse `M_PER_FT`, `WIND_SPEED` and `fToC` (`web/units.ts:3–10`); keep legacy precision on the default path and round once after converting. Keep missing values blank/unavailable, calm zero a real reading, and a tide height signed. This matches the display-only boundary of `web/unit-choice.ts:1,4–20` and the station's missing-reading path (`web/map/station-model.ts:85–94,136–139`).

- **Decide explicitly what each choice means.** Use the height choice for swell, rings, buoy seas and tide heights. For currents, recommend using the same speed choice as wind, with a follow-up label approval to clarify that in Settings; there is no current-specific preference and Settings calls it wind speed (`web/unit-choice.ts:4`, `web/app/UnitChoice.tsx:18–22`). Do not add another stored choice. For SST, convert absolute temperatures with the offset, but scale errors, differences, rates and band widths by `5/9` when going from Fahrenheit to Celsius—no offset. Preserve each rate's distance denominator when changing its temperature unit; in the contrast tap, make the primary rate match the legend and retain the alternate as explicit source context, not as a second unlabeled scale (`web/map/sst.ts:126–138,238`, `web/map/sst-bands.ts:47`, `web/map/contrast.ts:54–57,200`, `web/map/fronts.ts:182–187`). **UNVERIFIED:** user preference for a shared wind/current control and the proposed rate presentation.
- **Cards and HTML legends:** keep typed numbers and the original text for other consumers; give the Chart card a display-only descriptor with those numbers and render it from the current units and language. Do not re-parse strings or re-run the tap. The click stores a `ChartMark`, and the card already resolves language when it renders, but English currently bypasses the copy parts and some Spanish parts already contain rounded strings (`web/map/chart.ts:61,246`, `web/app/MarkCard.tsx:283,316–327`, `web/mark-copy.ts:41–57`). Format both languages from the same numbers. For legends, use the drawn numbers, not newly picked cutoffs; in particular SST can substitute the *band* endpoints, not the original analysis extremes (`web/map/sst.ts:356`). For ring text, convert the cap and show the equivalent pixels **per metre** by dividing the pixels-per-foot coefficient by metres per foot, or use plain scale wording with the converted cap; keep the drawn radius formula unchanged (`web/map/nearshore.ts:33–52,96–109`). Parameterize hard-coded bilingual units with the catalogue owner; do not strip suffixes out of translated strings (`catalog/app/strings.json:1205,2258,2273,2283`).
- **Map symbols and preview ramps:** update only label text on an already-loaded frame. Wind can refresh the label source independently of the arrows; the current engine/frame key guard would otherwise skip a preference-only update (`web/map/wind.ts:86–99,120–135`). For SST, retain the canonical contour level and major flag with its geometry; rewrite the label from that level without changing the contours, filters or image (`web/map/sst.ts:195–215,384–401`). For previews, keep numeric endpoints and the open-ended flag, then format visible ends and accessible names together at render (`web/app/PreviewLayers.tsx:38–43`). **UNVERIFIED:** renderer, no-refetch and open-card refresh behavior after implementation; qualify with offline fixtures.
- **Generated formats:** don't bake the device preference into generated TypeScript or hand-edit a generated table. If the traced SST band title needs style metadata, have the style owner change the authored source to expose numeric inputs and a unit-neutral template, then regenerate; the runtime still picks the language, units and precision (`style/layers-v1.0.0.json:234–249`, `web/map/sst-bands.ts:5,47`, `scripts/style/gen_style.py:361–380`). Leave reference/study formats alone until their consumers are verified (Section 1).

**What never converts because of this choice:** stored samples, canonical model fields, selection and safety comparisons, palette thresholds, availability, exports and GPX bytes. Keep the existing ingest normalization (for example station metres/m/s/°C to canonical values), and don't feed display values back into it. The model API keeps its own explicit query-unit contract; the Chart must neither rewrite it nor pass the preference into it. Planner export still gives its existing request to the exporter. Evidence: `web/unit-choice.ts:1,18–20`, `web/map/station-model.ts:56–62,75–86,99`, `web/map/swell.ts:381`, `web/map/contrast.ts:178–181`, `server/routes/om.ts:34`, `server/model-api.js:248–266,313`, `web/planner.ts:529–550`. **UNVERIFIED:** byte parity after implementation; use the same offline fixture and compare exports before and after toggles.

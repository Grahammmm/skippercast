# Service-worker cache strategy

## R1. Request classes

| Request | Strategy in the browser worker | Cache and evidence |
| --- | --- | --- |
| Navigation: `/` or `/index.html` | **Network first**, not `cacheFirst`. On a rejected fetch, return the precached `/` (landing), even for a query that would select the map online. An HTTP error is returned as-is. | `sc-shell-<build>` if complete, otherwise the most recently created retained shell containing `/`. `dist/sw.js:327–346`; online route selection: `server/routes/assets.ts:29–42`. |
| Navigation: `/map` | **Network first**. On rejection, try the saved `/map` key without the query. After 1,500 ms of a stalled fetch, an eligible saved page can win the race; if none is ready, the network can still win, including with an HTTP error. Without an eligible saved page, keep waiting for the fetch. | Normally `sc-pack-<region>-<time>`; the stall branch specifically requires a committed pack with a status-200 page and a parseable save time. The rejection branch uses the generic `fromPack` lookup (which also checks `sc-data`; normal navigation does not write `/map` there). `dist/sw.js:293–324,382–387,144–171`; `web/trip-runtime.ts:112–124`. |
| Navigation: other same-origin paths | **Network first**, with no offline page fallback and no runtime HTML write. Legacy `/downloads/*.gpx` bypasses even this handler. | None. `dist/sw.js:60–73,327–339`. |
| Fingerprinted `.js` / `.css` (`.<10 lowercase hex>.js` or `.css`) | **Precache** if listed; at runtime **`cacheFirst`** (ignore the query on shell lookup). On a miss, fetch and attempt to store a readable 200. On rejection, try the retained shell, then the generic saved lookup. | Writes to `sc-shell-<build>`; fallback can read an older complete shell and `sc-data` or committed packs. Matching uses the pathname suffix, not just `/assets/`. `dist/sw.js:43–47,73–79,341–364,382–387`. |
| Data: `/feeds/`, `/regions/`, `/data/` outside tile exceptions below | **`networkFirst`**. Save readable 200s; a returned HTTP error is not an offline trigger. On rejection, pick the newest saved answer by its save time. `/regions/` and `/data/` can match without the query after an exact miss; feeds normally require the exact URL. A newer habitat manifest replaces its pack counterpart only if its saved tiles cover every layer the pack had complete. | Writes to `sc-data`; fallback reads `sc-data` and committed `sc-pack-<region>-<time>`. `dist/sw.js:44,74–78,127–130,144–220,239–255`. |
| Tiles: same-origin queryless basemap PMTiles with `Range: bytes=N-M` | **Network first**, then exact saved byte range as HTTP 206 on rejection, using a synthetic `?sc-range=N-M` key. No automatic range write. Other range requests pass through. | Generic lookup reads `sc-data` and committed packs; the explicit pack writer populates the range keys. `dist/sw.js:49–50,60–62,106–110,382–396`; `web/trip-runtime.ts:87–102,186–195`. |
| Tiles: other same-origin requests | `/feeds/tiles/seafloor/` **passes through** (also on a range request); other non-range feed tiles, including habitat tiles, use the **data** rule. Ordinary static tiles such as `/tiles/*.pmtiles` without a Range header use the **static** rule below, not a separate tile cache. | None for seafloor passthrough; otherwise `sc-data` plus pack fallback for feeds, or static lookup with no runtime write. `dist/sw.js:59–80,239–255,376–396`. |
| Tiles: NOAA ENC WMS; OSM and other external maps | Recognized NOAA ENC `GetMap` grid tiles are **network first** with saved fallback only on rejection. The key normalizes layer set, size, zoom and cell; unrecognized requests and OSM tiles **pass through**. Browsing does not save ENC tiles. | Generic saved lookup on the synthetic key; the ENC pack writer supplies the entries. None for passthrough. `dist/sw.js:36–39,60–67,82–104,144–171,366–374`; `dist/offline-pack.js:135–143`. |
| `/api/` fetches: public allowlist | **`networkFirst`** data rule for the literal prefix regex `^/api/(?:forecast\|intelligence\|habitat\|daily\|om/)` (not a general public-API cache). | `sc-data` plus committed pack fallback. `dist/sw.js:41–44,72–73,239–255`. |
| `/api/` fetches: `/api/coast/report`, `/api/coast/ocean`, `/api/coast/history` | **Network first** for the plain GET variants; only a rejected fetch can use a complete explicitly saved snapshot. A query or fragment, `X-SC-Offline-Save`, Authorization, Cookie, non-GET or Range bypasses this special route. Ordinary browsing never writes a snapshot. | `sc-coastal-index` points to `sc-coastal-snapshot-<id>`; no `sc-data` or general trip-pack fallback. `dist/sw.js:32–35,60–73,258–290`; `dist/coastal-offline-core.js:24–31`. |
| `/api/` fetches: remaining routes (session, private trips, subscriptions, etc.) | **Passthrough**. A top-level same-origin GET *navigation* is classified as navigation before the non-navigation API rules; it does not add an API response to Cache Storage. | None. `dist/sw.js:41–44,60–79,327–339,399–408`. |
| Font files (same-origin WOFF2) and map label glyphs (PBF) | **Precache lookup, no runtime write**. A WOFF2 can be in the install list via the landing's static graph; a hashed WOFF2 is not a fingerprinted JS/CSS match. Chart's versioned glyphs go into the explicit map-pack list, not the install list. On a miss, fetch; on rejection, try retained shell then saved lookup. | `sc-shell-<build>` for listed install files, `sc-pack-<region>-<time>` for saved glyphs. `web/tokens.css:14–27`; `web/map/style.ts:17–20,146`; `scripts/precache.mjs:35–45,47–63,71–74,90–118`; `dist/sw.js:47,76–79,349–353,376–387`. |
| Other same-origin static GET subresources (including icons/manifest) | **Precache lookup, no runtime write**: cache hit first (ignore query), then fetch, then retained shell or saved lookup if fetch rejects. This is not the runtime-writing `cacheFirst` used for hashed JS/CSS. `/sw.js` and `/precache.json` subresource requests **pass through**. | `sc-shell-<build>` for listed files, fallback to retained shell or generic saved lookup. None for passthrough. `dist/sw.js:68–80,349–353,376–387,399–408`. |
| Cross-origin (other than ENC above) | HTTPS `api.tidesandcurrents.noaa.gov` and `api.weather.gov` use **`networkFirst`** data; all other origins **pass through**, including external fonts and ordinary tile hosts. NOAA tide predictions can fall back across date windows for the same station/interval/datum/units/time zone when there is no exact hit. | `sc-data` plus committed pack fallback for the two hosts; none otherwise. `dist/sw.js:45–46,60–67,132–171,239–255`. |
| Non-GET or Range (unless the basemap exception above) | **Passthrough**, meaning the worker does not call `respondWith`; normal browser HTTP handling still applies. | None. `dist/sw.js:60–62,399–408`. |

This is source and offline fixture evidence, not a live visit.

**What actually goes into the install:** `shells` is just `/`, not every HTML page and not `/map`. `assets` starts with the output JS/CSS fingerprint list, subtracts files reachable only from the app/landing roots (including the app's early script), then adds back the landing's first-paint graph: static imports, styles and hashed resources such as fonts, not the landing's dynamic night-map import. `static` is the matching top-level app icons, Apple touch icon and web manifest. The worker takes the deduplicated local-path union of those three lists. It does not install the `warm` or `v2` lists: the landing's warm-up makes low-priority requests for app startup files, and an explicit save reads `v2` for app assets (skipping the terrain renderer subtree) and versioned glyphs, then saves `/map` under its stable key. Sources: `scripts/precache.mjs:35–118`; `dist/sw.js:411–424`; `web/landing/warm.ts:1–7,24–33`; `web/trip-runtime.ts:112–124,167–185`.

Saved data responses are marked with `X-SC-Offline` carrying the original saved timestamp (`dist/sw.js:112–125,239–255,286–290,370–386`). An install-shell hit is returned unchanged, not marked by that helper (`dist/sw.js:327–339,355–379`). `web/offline-response.ts:7–20` interprets the marker without fetching or storing anything. `web/shared-fetch.ts:25–49,111–149` is a separate in-page sharing layer for unqueried same-origin static JSON/GeoJSON; it does not change the service worker's rules. Likewise HTTP cache headers are not Cache Storage eviction rules (`scripts/client-build.mjs:32–58`; `dist/sw.js:223–245,355–363,437–445`).

## R2. New build, open tabs and withdrawals

1. **Publish the new bytes at the same URL.** The client build runs Vite, copies static files (including `dist/sw.js` via `STABLE`), hashes the output asset names and page names/content, stamps and renames HTML, then writes `precache.json` and substitutes `BUILD` in `sw.js`. A change that does not alter those hash inputs need not make a new build ID. The server Worker resolves stable page URLs through the built `SHELLS` map and serves mapped pages with `no-store`. `/sw.js` stays stable and gets `no-cache`; the smoke script requires revalidation. The build checker verifies the precache URL inventory/targets and the stamp. `scripts/client-build.mjs:30,104–113,143–168,195–207`; `scripts/precache.mjs:122–133`; `scripts/build-worker.mjs:13–24,28–34`; `server/routes/assets.ts:92–114`; `scripts/check_client.mjs:97–128`; `scripts/smoke_test.sh:50–53`.
2. **Install on the browser's update check, not on a deployment timer.** The trip and push paths register the classic `/sw.js`; saved-pack/snapshot app startup can register it again. The Add to Home Screen prompt code is separate. On install the worker requests `/precache.json` with `no-cache`, loads the selected URLs with `reload` using all-or-nothing `addAll`, then calls `skipWaiting`. A failed precache logs a warning but still lets the worker install and skip waiting, so push can work. The built files are checked for a matching build stamp, but runtime `precacheList` does not compare the fetched manifest's build to `BUILD`. `web/trip.ts:109–112,235–250`; `web/trip-runtime.ts:281–288`; `web/alerts.ts:365–370`; `web/install-app.ts:14–28`; `dist/sw.js:3–7,411–448`.
3. **Activate, prune, claim.** If the new shell contains `/`, activation deletes every other `sc-shell-*` cache, then calls `clients.claim()`. If not, it still claims clients and leaves old shells in storage. Offline landing can use the newest retained shell with `/`; subresources try that retained shell only after a miss in the current cache and a rejected fetch. The `skippercast-offline-status` message can retry installation of the shell and prune once ready; there is no tracked production sender for that message in this tree. Reproduce: `git grep -n -E 'controllerchange|skippercast-offline-status|skippercast-shell' fdd69c9aa114e8020aa8e82dbc9b0d2dcad29fec`. The matches are the worker handler/reply and its test, not a page reload or retry sender. `dist/sw.js:327–363,426–458`; `tests/test_sw.mjs:254–319`.
4. **Control can switch without replacing the open document.** After activation the new worker can handle later requests from an already-open tab, but `clients.claim()` does not reload that tab. The tab sees new HTML on an online reload or new navigation that reaches the current server; there is no app-driven refresh on controller change (search above). An old open document can still request its old fingerprinted URLs, and a new-cache miss that gets a 404 is not repaired by fallback. The browser's update-check timing and the moment a tab next navigates are not measured here. `dist/sw.js:304–339,355–364,437–450`; `server/routes/assets.ts:107–114`.
5. **Withdrawal/rename is not a purge of the visitor's storage.** On an online navigation the old worker already asks the server; the server's redirect (for example `/coast.html` to `/map?presentation=3d` unless a presentation is specified) or 404 wins. For an unmapped browser page link, the server can return a branded, `no-store` 404 when the asset is missing and the request is eligible. Arbitrary old pages are neither in the install list nor replayed as offline navigations. The important exceptions are the landing at `/` (also the offline answer for `/index.html`) and `/map` saved in a pack: the former can be from a retained older shell after precache failure, and the latter can still show the saved page on fetch failure or a stall even after a successful worker upgrade. No per-URL tombstone is written on 404; shell cleanup removes a whole build, and packs survive it until replaced or deleted. `server/routes/assets.ts:18–27,77–114`; `scripts/precache.mjs:44,107–118`; `dist/sw.js:293–353,437–458`; `dist/offline-pack.js:157–169`; `web/app/Trip.tsx:155–160`.

## R3. What can grow

| Store | Application bounds and cleanup |
| --- | --- |
| `sc-shell-<build>` | The build checker bounds the install payload at **802,383 raw bytes**, including resolved `/`; it separately caps the `v2` asset/glyph list at **3,810,000 raw bytes**. These are build checks, not runtime limits. Runtime JS/CSS additions have **no entry, byte or age bound**. A complete newer shell deletes old shell caches; repeated failed precaches can retain older caches and leave incomplete ones. `scripts/check_client.mjs:105–124,176–196`; `scripts/startup-budget.json:14–18`; `dist/sw.js:355–363,418–458`. |
| `sc-data` | **150 entries** after a successful put and trim (drops the first keys in cache enumeration order, not least-recently-read). Best effort, not a hard byte or age limit; saved timestamps select fallback or explain provenance, not expiration. Survives upgrades. `dist/sw.js:27–35,144–171,223–225,239–255,437–445`. |
| `sc-pack-<region>-<time>` | **No total pack-byte limit, age limit or limit on number of saved regions** in this saver. Normal successful resave keeps one pack per region by best-effort cleanup; failures or interruption can leave old or incomplete caches, and only commits with metadata can answer. Component limits are not whole-pack caps: ENC and basemap each plan up to **1,500 tile cells** at map zooms 8–12 (basemap cells can use multiple archive ranges); the ocean phase has its own **12,000,000-byte** budget. The build-time `v2` cap excludes the page and other pack contents. Packs survive worker upgrades and can be deleted by the visitor. `dist/offline-pack.js:95–169`; `dist/offline-core.js:4–8,33–54,65–86`; `web/trip-runtime.ts:167–200`; `web/map/ocean-pack.ts:13–16`; `dist/sw.js:144–159,437–445`; `web/app/Trip.tsx:155–160`. |
| `sc-coastal-index` / `sc-coastal-snapshot-<id>` | One committed pointer to three products, capped at **8 / 8 / 16 MiB** respectively and **32 MiB** combined for product bodies (plus metadata). A replacement stages a candidate alongside the old snapshot and sweeps old/orphaned snapshots; failed cleanup can leave bytes behind but does not make those copies eligible. No storage age limit: date validation rejects future dates, not old snapshots. Explicit deletion clears the family; a worker upgrade does not. `dist/coastal-offline-core.js:2–7,15–34`; `dist/sw.js:273–284,437–445`. |

## R4. Follow-up

No implementation unit is needed to complete this report. In particular, this audit does not set a withdrawal guarantee for disconnected devices, change retention, or add a reload on update. To replay the existing install, retention and saved-map checks offline (no browser registration), run `node --test tests/test_sw.mjs tests/test_precache.mjs tests/test_precache_order.mjs`.

## R2. One-way keys and history

- **Written but never read:** none in the inventoried source handlers. The legacy first-run marker has a reader in its own helper, but no live wizard caller found; do not count it as a current onboarding dependency. The planner draft is not write-only just because it doesn't mention `localStorage` by name (`web/trip.ts:48–56`, `dist/browser-storage.js:1–6`).
- **Read but never written on this main:** `skippercast-tide-station-v1.<region>` only; the reader writes the different v2 key and may remove v1 (`web/tide-stations.ts:27–52`). Test seeding is not a production writer.
- **Unversioned keys:** no change of serialized type or field layout found in the available history. `skippercast-chat-open` stayed a `1`/`0` string. `skippercast-first-use-boat` stayed `ask`; “Keep a carried boat-entry request when session cleanup fails” changes when the read is honored, not the bytes, and “Keep the app catalogue off the landing path” moves the same helper into `boat-ask.ts`. The account return key stayed a hash string in the readable revisions. The current `web/account.ts:16,87–88` bare `#` vs legacy `dist/account.js:1245` `#guide` is a fallback-value difference, not a new layout (if counting value semantics as a change, “MAPLIVE-1: private, lazy, off-by-default map-style preview layers on the real app map” introduces the web writer). Writer/reader lines were compared from the local postimages back to the file additions; no lazy fetch.
- A version tag does not guarantee an immutable shape: the layers v1 reader migrates a bare string to a profile map under the same key (`web/state.ts:254–259`). Tide stations use a new key instead (`web/tide-stations.ts:35–45`).

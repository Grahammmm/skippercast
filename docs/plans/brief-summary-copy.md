## 2. Units and rounding

Use the brief's device display choices, independently of the language: knots, mph or km/h for wind and gusts; feet or metres for offshore seas, surf and surge (including heights in reasons and limits). Read the unrounded values in knots/feet, use the existing factors and labels, and only then format for the chosen language. Seconds, percent and chlorophyll concentration keep their units; format times in the region's zone and lists/plurals in the chosen language. No temperature is part of these sentences. Never convert a number embedded in a name or source alert (`web/unit-choice.ts:1–20`; `web/units.ts:3–10`; `web/i18n-core.ts:60–68`; `daily.ts:206–208,280–305,308–316,332–376`; `spear.ts:148–170`).

**Proposed display rule:** on the localized path use tenths for range endpoints. Round the converted low down and high up, and round an equal-endpoint reading, a reported peak gust or a reported peak height up. Only collapse a true equal-endpoint range. Format the resulting values with up to one decimal place; make sure the formatted upper value still covers the unrounded converted maximum, including near decimal boundaries. A threshold such as a user's limit is not a forecast maximum; do not round it as if it were one or compare the display digits. Keep the existing English/default-unit string byte for byte: the no-understatement rule applies to newly formatted readings, not the unchanged legacy strings, whose current nearest-tenth formatting can round down (`daily.ts:83–90,163–171,206–207,287,359–360`; `limits.ts:95–101`; `web/i18n-core.ts:65`).

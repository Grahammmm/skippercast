# What SkipperCast prints or saves as PDF

| If you want to save… | What the source says |
| --- | --- |
| The Brief | Use **Print this brief**. The app substitutes a light text layout for the map and adds place, forecast lead time, print time and a stale-copy warning (`web/brief/Brief.tsx:951–964`, `web/brief/brief-print.css:12–39`). |
| A Chart, Terrain view, or map overlay | Browser Print is **not a map export**. The app hides the entire map stage, legend and dock (`web/app/MapStage.tsx:230`, `web/brief/brief-print.css:13–18`). |
| Conditions or History | **Desktop loses the selected panel entirely** because it is inside the hidden stage. Phone puts the panel in the sheet instead; its body is not hidden by the print rule (`web/app/Desktop.tsx:68–73`, `web/app/Mobile.tsx:253–267`, `web/brief/brief-print.css:13–30`). |
| Trip, its Saved Spots list, or the Float Plan form | **None of the dialog contents prints**, even when open. Downloaded trip notes are a separate HTML document and can contain the validated Float Plan (`web/app/Trip.tsx:75–96`, `web/app/Planner.tsx:304–308,363`, `dist/trip-export.js:185–213`). |
| Plan or in-app Reports | **Phone is the better candidate (estimate)**: the phone page is put in normal flow; the desktop overlay remains absolute and scrollable (`web/app/app.css:448–461`, `web/brief/brief-print.css:25–31`). Neither has its own print layout. |
| The public coastal report or public information pages | The report and other pages using `coast-readable.css` have a separate light print layout. Other public pages depend on their screen CSS and the browser (`dist/coast-readable.css:107–118`; page inventory below). |

## R1. Inventory and rules

The exported standard notes rule is `body {padding:0}` and `article {break-inside:avoid}`; it hides nothing (`dist/trip-export.js:210`).

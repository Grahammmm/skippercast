## R1. From the link to the screen

1. **Serve the shell, not a region redirect.** `/map` always serves the app; `/` and `/index.html` also serve it when the `region` key is present, even if empty. The Worker clears the search only on its *internal* shell fetch, not the visitor's address. Its known-ID lookup is for a preload, not admission (`server/routes/assets.ts:16,34–42,107–129`; `server/config.ts:8`; `scripts/build-worker.mjs:9–11,33–34`). `/coast` and `/coast.html` redirect to `/map`, copying the query and supplying `presentation=3d` only when absent; `/sources/` likewise preserves its query (`server/routes/assets.ts:23–26,104–106`).
2. **Read and keep the ID.** `dist/app.html:49` starts `web/app/boot.ts:15–23`, which imports the app regardless of its Chart warmup hint. The app enables the v2 store and starts URL sync (`web/app/main.tsx:31–35`; `web/state.ts:393–403`). `readURL` reads `region` with `URLSearchParams.get`, and `syncFromURL` uses that string as-is (`web/state.ts:159–169,317–321,333–342`). Fish aliases such as `place=cambria` fill a region only if **neither key** `region` nor `coast` exists; they do not rewrite `region=cambria` or fill `region=` (`web/fish-links.ts:5–10,33–37,53–60`). If both resolved geography values are falsy, the app calls `savedHomeURL` and replaces the address; saved port, saved legacy place, then cookie, otherwise landing. The interim shell can say “No port chosen” (`web/app/main.tsx:47–48`; `web/app/Masthead.tsx:62–63`; `web/strings.en.generated.json:916`; `web/ports.ts:194–220`).
3. **Fetch the named package, not the index.** App startup renders and calls `loadRegion(id)` for a nonempty ID (`web/app/main.tsx:61–81`). The reader requests `regions/<encoded-id>/region.json`, requires the same ID, a name, valid center and valid/default zone, and never checks status or index membership (`web/app/region-info.ts:43–74`). Drafts are skipped before output generation (`src/skippercast/platform/build.py:90–101,176`), and the Worker build serves static `dist` copies, not source configs (`scripts/build-worker.mjs:13–24`; `scripts/client-build.mjs:104–113,195–205`; `wrangler.jsonc:12–15`). The committed census has 16 package JSON files and 16 index entries, with exactly the same IDs: 1 active and 15 preview. All six draft IDs lack both. Index `default_region` is not the v2 fallback; the legacy reader in `dist/region.js:33–40` has a different contract.
4. **Render the successful package, or disclose the read failure.** `web/app/App.tsx:99–133` publishes `ready` only for a current request; 404 becomes `missing`, other status/body/timeout failures become `error`. Desktop and mobile use the shared `Location` (`web/app/App.tsx:144–150`; `web/app/Mobile.tsx:244`). It shows name and coordinates, or the quoted missing ID and a Choose a port link to `/` (no Retry for 404; other failures offer Retry). Where to look reads the current missing state and ranks nothing (`web/app/Masthead.tsx:55–76`; `web/brief/WhereToLook.tsx:69`; `tests/test_region_missing.mjs:70–108`). The stage takes the matching region's center; a valid explicit camera can override it, and a bare link with no center never starts a Chart (`web/app/region-info.ts:34–40`; `web/app/MapStage.tsx:215–225`; `web/map/stage.ts:203,494–497,639–642`; `web/map/chart.ts:294–300`).
5. **Preview and picker are separate.** A matching *ready* `/data/home-ports.json` result with any preview port adds “Preview” and “Forecasts and readings are live; habitat ranks, coastline and some layers are incomplete here.” No matching port, loading, or failed directory means no badge, not an “Active” label (`web/ports.ts:243–252,282–289`; `web/region-preview.ts:4–11`; `web/app/Masthead.tsx:55–73`; `web/brief/WhereToLook.tsx:318–322`; `web/strings.en.generated.json:46–47`). The landing's Browse regions disclosure is lazy and user-opened. Inside it, the coverage snapshot can list draft rows, but Open is disabled for a draft; missing map links do not open this picker. Morro Bay is the picker's default selection, not a fallback Chart (`web/landing/PortInput.tsx:109`; `web/RegionPickerEntry.tsx:15–26`; `web/landing/RegionPicker.tsx:7–16,27`; `web/region-coverage.ts:35–38`).

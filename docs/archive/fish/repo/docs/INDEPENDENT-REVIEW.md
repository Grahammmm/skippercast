# Independent source, transport and integration review

Reviewed October 1–2, 2026 by a separate implementation/research agent. This is a source-code, dataset and local HTTP/library review. **Live browser visual QA was blocked by the available browser administration policy and was not performed.** No claim of visual beauty, mobile usability, rendered accessibility or browser frame performance follows from this review.

## Product and source checks

Primary publisher documentation was checked for Windy, Windfinder, Surfline, Windguru, Fishbrain, Kongsberg OceanView, Palantir and Anduril. The resulting design principles are synchronized map/time selection, explicit field scales, native source timing, progressive provenance detail and observation playback separate from forecasts. Full app walkthroughs were not claimed; Fishbrain pages returned 403 and the available computer-use inventory exposed no controllable browser. References and limitations are in [PRODUCT-DESIGN-RESEARCH.md](PRODUCT-DESIGN-RESEARCH.md).

Actual NAIP and GOES service responses and sample images were inspected. NOAA CUSP original creator/date/accuracy properties were retained in a bounded contextual shoreline extract; unavailable tiles were not certified empty. Actual public SkipperCast WCOFS/HF-radar frames were normalized with source age, native times, cells and direction retained. Tests exercise stale/future observations and missing support; arrows do not invent a continuous flow field. NAIP is dated aerial context, GOES is acquired longwave imagery, and HF radar is surface observation. None supplies dive visibility, bottom temperature or tomorrow's satellite scene.

The bathymetry importer reuses only the three reviewed public-domain USGS original ZIP/native COG identities. Native producer masks, nominal 0–300 ft gates, transparent gaps, nearest display sampling and coarse-depth lighting exclusions were checked. The unknown vertical datum and producer interpolation uncertainty remain explicit. Original measured-grid display and relative species habitat fit remain separate layers. See [BATHYMETRY-OVERLAY.md](BATHYMETRY-OVERLAY.md) and [SKIPPERCAST-BRIDGE.md](SKIPPERCAST-BRIDGE.md).

## Concrete findings and resolution evidence

| Finding | Resolution observed in source |
| --- | --- |
| Bathymetry placed beneath the coarse overview land fill could obscure real nearshore bottom. | Raster insertion moved above the land/imagery base and below coastline/context layers. Pixel masks, rather than a coarse land polygon, define bottom coverage. |
| A bathymetry tile failure could leave its depth legend claiming availability. | Map error handling now clears bathymetry state, hides its layer and reports unavailability. Browser event-path execution remains untested. |
| Paused GOES playback could label an older displayed frame with the latest acquisition timestamp. | Description now uses the displayed `cloudTime`; replacing the satellite product resets playback index/time and updates existing source tiles. |
| A rolled-out forecast hour or report-refresh day change could leave the map clock different from the briefing's silent fallback hour. | `renderAll()` now validates the selected calendar date and hour against supported data before rendering; unavailable forecasts stop playback. |
| Ocean/shore/history products were loaded only at page initialization, then expired without recovery. | The bounded periodic report refresh now also refreshes these products while retaining original source clocks on failed retrieval. |
| MUR/MPA geometry was initialized once, so refreshed metadata could describe old geometry; stale MUR lacked a clear notice. | Re-read the correction: source clocks drive GeoJSON upserts on update; the MUR popup reads the current analysis clock. Display, description and unavailable notice share freshness checks. Rendered update behavior remains untested. |
| Mobile SVG axes could shrink to about 5 px when an 840-unit chart fit a narrow screen. | Re-read the correction: hourly charts retain 840 px display width, history/season charts retain 900 px width, and narrow screens scroll horizontally with visible instructions. Axis text is no longer compressed to fit phone width. Final rendered legibility remains unverified. |
| Terrain-score colors were labeled as relative species habitat fit. | Update now colors reef fills by the selected species' ordinal fit 2/3, with a matching discrete legend. Separate depth imagery retains its own 0–300 ft color scale. |

Other checks confirmed species/depth filters retain whole nominal-depth polygons, current arrows use actual native cells/times with missing cells blank, future radar selections are withheld, CDIP readings retain native sample times, and satellite imagery is not presented as a future-day forecast. Protected-water depth imagery is physical context; screened fishing habitat still depends on its separate reviewed transport and legal-screen gates.

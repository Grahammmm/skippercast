## 3. Immutable receipts, review rounds and bad-evidence outcomes

Implementation reconciliation: [Admission producer adapters and PC-9 serialization](admission-producers.md) defines the corrected unreleased-v1 campaign/discovery evidence shapes, exact execution encoding and enumerated native references. It does not change the rev4 execution API or authorize execution.

### 3.1 Shared shapes and hashing

Every NEW campaign workflow receipt has schema, created_utc, author_profile, author_model (actual runtime, not requested alias), card_id, code_commit, skill_commit. Plan receipts also have campaign_segment_id, coordinator_segment_id, plan_id, plan_sha256. Review receipts add review_round, attempt, context Ref. Producer-native receipts remain byte-for-byte in their original schema and encoding; adapters do not rewrite them to this common header.

Canonical new JSON bytes: json.dumps(sort_keys=True,separators=(',',':'),allow_nan=False) + newline, UTF-8. Finite numbers only. O_EXCL, fsync, no self-hash. A Ref is {root_id,path,sha256,bytes}; sha256 is lowercase 64 hex of FULL FILE BYTES. Hash of a file belongs in its consumer or handoff, never the file itself. Object digests such as plan_sha256 use the producer algorithm WITHOUT newline; name these separately. Schema-specific observation fields are NOT Refs (3.4).

Schemas B1a owns (same v1 names are safe only because no released implementation exists): coast-admission, coast-enqueue-receipt, coast-run-summary, coast-review-context, coast-tier1-screen, coast-tier2-check, coast-review-packet, coast-open-report, coast-review-verdict, coast-segment-ledger, coast-archive-manifest, coast-release-list, coast-review-routing. Each has strict required fields, no self-hash, typed normal/error variants; scripts' small intermediate stats/text/vision/metrics/release receipts have their shape documented alongside their owner and are validated in owner tests. B1a fixtures must materialize complete instances with real hashes, not literal '<64 hex>' placeholders.

Required payloads:
- admission: campaign Ref; plan_file Ref; segment_record Ref; catalog/discovery Refs; sources with raw provenance, retained derived inputs, hot-cache Refs, rights/datum/reader; grid definitions; windows with window_key/window_dir/source/grid/idx/pixel window/owner/footprint; budgets and before/delta usage; dry_run Ref with would_enqueue_count=len(producer list), selected/held IDs; preconditions; holds. No holds means metadata admission only.
- enqueue: admission and bridge Refs; code/deps hashes; fixed store path; jobs in receipt index order {window_key,source_id,root_job_id,input_manifest Ref,new_row}; intent Ref. The producer bridge's plan/segment fields must agree.
- run-summary: section 2 payload, admission/enqueue/bridge Refs, immutable output pointers for each stage; cells summary copied faithfully (count,min,max,mean,p80, including producer 'unknown'); absent values separately labelled, never advertised as producer median.
- review-context: independently posted admission/run/bridge/enqueue Refs, root bindings IDs, posted-hashes Ref, routing/threshold/prompt Refs, review_round, attempt, supersedes Ref/null, correction_verdict Ref/null, run author actual model and card provenance. Does NOT pin downstream tier files (avoids a cycle). The author/card provides this independently of the packet; no 'latest file' directory glob.
- tier1: context, run Ref, exactly one entry for every admission window, stage state, deterministic producer fields, derived measurement records, text/vision raw-response Refs and verdicts, thumbnails when mapped, flags and status pass/flag/held/unavailable; summary counts and measured latency/tokens/endpoint/model/prompt SHA/slots.
- tier2 check: context, mode, verified input Refs, diagnostic observations for broken refs, findings {window_key|null,severity must|should|info,code,detail,evidence Refs}, counts and wall_s.
- packet: context, admission/run/tier1/three check Refs, sources/lane, actual run-author provenance, flags union, population, sample, routing Ref/reviewer requirement and optional measured author minutes. No packet_sha256. Diagnostic variant has integrity_ok=false, null populations/sample and must findings; it can route correction but never semantic acceptance.
- open-report/verdict/ledger/archive/release: sections below.

### 3.2 Round and attempt protocol

r01/a01 is the first review. Retry of a failed tier command uses a NEW a02 directory and a NEW context with supersedes=a01/context Ref; every tier reruns into that attempt with explicit input bindings, not 'latest' discovery. No reuse/overwrite of existing stats, thumbnail, text, vision, checks, packet, report or verdict. Completed round r01 must_fix creates correction then r02/a01; r02 context pins r01 verdict and the exact corrected/new run summary (or unchanged run when only paperwork changed). r1 file bytes remain unchanged; all r2 consumers pin r2 evidence, except explicit supersedes/correction references and immutable unchanged producer inputs. Continued runs use runs/run-NN.json independently of review round numbers. Pipeline stages keep their own lease attempt directories.

The context must be created by reviewed prepare_round.py from explicit trusted handoff pins and admissions. Missing posted hash is a diagnostic finding, never a hash silently invented from current disk and called posted. It may create a diagnostic context with observations and no claimed valid run Ref if handoff evidence is missing; semantic acceptance is unavailable until corrected. Only independently authenticated plan/card identity is used on that path. If even identity/author is unavailable, request corrective handoff on the current card; do not append a verdict to an unrelated plan ledger.

### 3.3 Sampling, adjacency and independence

eligible = verified map_done windows whose Tier1 is pass, no required-unavailable evidence, and no tier1/tier2 must/should flag. flags include ALL held, unfinished, failed, integrity and unavailable windows as well as quality findings. All flags and a sample are examined. target=max(8,ceil(0.125*map_done)); size=min(target,len(eligible)). seed=SHA256(UTF8(plan_sha256+':'+bridge_receipt.sha256)). Rank by SHA256(UTF8(seed+':'+window_key)), tie-break window_key, take size, report sorted keys. Empty eligible is valid but never evidence of a clean map. Regression sizes for done/flagged 0/0,1/0,4/0,16/12,16/16,16/2 are 0,1,4,4,0,8.

Adjacency only for same source SHA + grid_sha256; idx gives r=idx//cols,c=idx%cols. Neighbours left/right/up/down constrained to row/column bounds and idx<total (ragged final row). Prior accepted plans may supply neighbours only via pinned ledger snapshot and exact retained Refs; never cross source/grid. No neighbours is structurally not_applicable. Missing expected neighbour output is unavailable, not no neighbours.

Routing config is operator-owned, versioned and hash-pinned; defaults here do not alter operational profile routes. Record ACTUAL author and reviewer models plus hash-bound runtime provenance. No profile-name fallback for missing actual model, and no guessed mapping from aliases. Reject same actual model, disallowed model-family pairs from the admitted policy, unqualified reviewers or uncertain provenance. Non-Sol design/code may receive qualified Sol review; Sol-authored work needs qualified Astra/Claude per current authorization or holds for the operator. A profile called opus-coder is not proof it is Claude. A held model route is never silently substituted. Local/T2 checks are not the independent semantic review. This card uses the developer-required named reviewer opus-coder, who must verify actual different-model Sol/Claude provenance before reviewing this Astra revision; if unavailable, hold rather than review Astra-on-Astra.

### 3.4 Executable integrity-error verdict

open_packet.py ALWAYS writes a new open-report.json on a bounded readable input set, even when returning exit 3 for an integrity defect. It takes trusted context and the handoff's expected packet hash independently. Validate context identity/routing before reading packet content. Report fields: trusted context Ref, expected_packet {root_id,path,expected_sha256,expected_bytes}, observed_packet {status present|missing|unreadable,observed_sha256|null,observed_bytes|null}, integrity_ok, problems[] with code/path/expected/observed values, verified_refs[], measurements_trusted boolean. Observations are evidence ABOUT an expected file, not valid Refs to it; do not recurse through expected/observed objects. If readable invalid bytes must be retained, copy them unchanged to an evidence snapshot in the attempt and pin that snapshot as a normal Ref. Never parse arbitrary malformed content for plan identity/author or population.

write_verdict.py accepts --open-report plus --context and decisions; it does not require the broken packet chain to validate for a corrective verdict. Integrity-error variant has verdict=must_fix, evidence_status=invalid, packet=null, open_report Ref, expected/observed packet observation, must_fix from diagnostic codes, windows_examined=[], population=null, tier1_confusion=null, tier2_packet_accuracy=null, metrics_unavailable_reason='integrity_failure', next_tile_card_authorized=false. It validates trusted context and the report's own bytes/routing, not the bad target. A normal verdict requires open-report integrity_ok=true and revalidates every pinned input immediately before append. No accept/hold input can override the integrity-error variant. A missing expected source or changed tier input likewise produces a must_fix verdict, not an external blocker.

The ledger normal verdict row pins verdict and validated packet. Integrity-error row pins verdict + open-report + context only; packet=null, status=must_fix. The invalid expected hash is a diagnostic scalar, not an unresolved ref. On this error branch the context edge has validation_scope=identity_snapshot: verify the context FILE bytes, schema, independently posted identity and author provenance, but treat its downstream run/producer pins as recorded EXPECTATIONS, not assertions that they currently resolve. The report lists which expectation failed and which references were successfully verified. The normal branch uses validation_scope=full_graph and cannot opt down to identity_snapshot. The same rule applies when the changed file is the run summary directly pinned by context, not just a tier file. B1a must encode these edge roles, not implement indiscriminate recursion into every dictionary containing a hash. A corrupted context file itself cannot use this exception: retain its observed bytes and issue a corrected independently authenticated diagnostic context first. The generic validator understands this discriminated union: receipt self-consistency may pass while the SCIENTIFIC chain remains invalid. Never use that pass for acceptance or release.

Tiny structural example (not a substitute for B1a's fully hashed fixture):
  verdict: {evidence_status:invalid, verdict:must_fix, packet:null, population:null, tier1_confusion:null, open_report:Ref, must_fix:[{code:HASH_MISMATCH}], next_tile_card_authorized:false}
  ledger: {kind:verdict, verdict:must_fix, packet:null, verdict_file:Ref, open_report:Ref, context:Ref, prev_row_sha256:previous_line_hash}
This graph has no dependency on the bad object's claimed hash and no cycle.

## 4. Reference namespaces, ledger and archive/release

### 4.1 One confined resolver

root_id values: queue:<campaign_segment_id> -> C; repo:<code_commit> -> pinned SC_REPO; archive:<campaign_segment_id>:<close-id> -> A; raw:campaign -> ARCHIVE_ROOT/raw. Raw paths omit the literal raw/ prefix (it is in the root binding). No absolute paths inside Refs. New workflow files require root_id explicitly. Existing producer-native {path,sha256,bytes,...} is interpreted ONLY by a schema adapter as queue-root relative. Root-relative strings such as a Store input path cannot be guessed from suffix; enumerate known producer schemas. Unknown external path-bearing fields cause unresolved-reference refusal at close, not a silent omission.

Before opening, reject absolute/traversal/invalid components and symlinks in every path component including configured root path; reject nonregular leaves. Confine with directory-FD/no-follow traversal, check size and full hash. Roots are given by the operator/card binding, not receipts. Discovery source URLs are provenance strings, NOT file refs, never fetched by validation. Pin raw-manifest ROW bytes and a retained copy of the relevant source manifest snapshot under queue provenance; do not pin an append-growing entire live manifest without a snapshot.

Examples: queue:C1-morro-bay + cache/source-a/file.tif; repo:<commit> + skills/coast-campaign-shared/config/tier2-thresholds.json; raw:campaign + source-a/file.tif; archive:C1-morro-bay:close01 + products/<window_dir>/map/<lease>/terrain.tif. Each is a Ref with actual file SHA and byte count in materialized fixtures.

### 4.2 Ledger ownership and ordering

Only write_verdict.py appends kind=verdict; only archive_segment.py appends kind=archived; both call coast_ledger.append with flock on ledger.jsonl.lock, verified existing chain, O_APPEND, fsync. Each canonical JSON line has seq and prev_row_sha256=SHA256(previous line INCLUDING newline); genesis=64 zeroes. Never embed own hash. Idempotency key is (kind, campaign_segment_id, plan_sha256, review_round, attempt) for verdict, (kind, close_id) for archive. Same key/same bytes returns existing row; same key/different payload refuses. Campaign index uses a separate chain and pins the segment row hash (not a copy of the segment prev hash); cross-file append crash is reconciled idempotently by the SAME writer, no acceptance announcement until both rows exist. No raw board/Store/Flock ledger writes.

Closure is separate from qualification success. An accepted evidence verdict can include a held window with an explicit accepted_cause and no map product; it is not map acceptance. A normal accept requires no unresolved integrity/budget/scientific must-fix, all flags/sample addressed, all holds dispositioned. Every unfinished inventory item prevents segment close. Archive closure requires frozen campaign inventory fully accounted for, latest selected verdict accept for every current plan, no pending correction/replacement, and every final window map_done or held/failed_terminal/cancelled with an explicit accepted closure cause. Never close a segment merely because all existing rows happen to be accepted while planned windows are missing.

### 4.3 Complete retained graph

Archive is a new close-id directory, never overwritten. Freeze workflow under campaign close lock; refuse active execution leases/controllers or further admissions during close. Capture ledger tip and campaign inventory. Collect from admission/context/ALL selected and superseded review receipts, discovery, enqueue and committed lineage results; traverse every supported producer-native ref including native-job source, source_row/evidence, observation, mapping-input source/auxiliary/derived inputs, run input, cells, terrain, support, thumbnails, stats, prompts/config, raw manifest snapshots, result/job/log provenance. Retain lease ID in product destinations to avoid overwriting retry evidence. Exclude only ephemeral runner scratch, live leases and live SQLite; save a verified summary/lineage snapshot instead. If a required ref points to excluded scratch, stop and reconcile; exclusion never hides a scientific dependency.

ARCHIVE-MANIFEST files contain {source_ref, retained_ref} with IDENTICAL hash/bytes. retained_ref is archive-root or raw-root. Queue cached originals can map to raw only when exact hash/bytes equal a pinned immutable raw source. Queue cached DERIVED data (e.g. VR-derived GTiff) not identical to raw must be copied to archive inputs/<sha>/<safe file>, together with its derivation receipt and original BAG/raw ref. Preserve auxiliary masks and metadata similarly. Repo config/prompt bytes are copied into archive config/<commit>/...; future verification never needs a checkout. Many source paths may map to one content-identical retained object; one source ref cannot map ambiguously. Preserve original receipt bytes; do not rewrite embedded refs to achieve closure.

Archive resolver: for every original (root_id,path,sha256,bytes), look up the exact source_ref key in the manifest; resolve retained_ref against archive/raw ONLY. Native nested refs get the original queue namespace from their producer schema even though their containing bytes now live in archive. Do NOT resolve them against the containing archived directory. Broken historical targets from integrity-error verdicts remain observations, while their valid diagnostic snapshots are retained. Historical identity_snapshot context edges retain the exact context bytes and the open-report's verified refs/observed snapshots; the expressly failed expectations are diagnostic leaves, never silently asserted valid. They cannot supply scientific product provenance for closure. A previously pinned NORMAL r1 ref whose bytes were actually corrupted requires restoration of those exact original bytes from retained provenance before closure; a later r2 verdict does not erase that historical preservation obligation.

Ordering (acyclic): copy + hash all retained objects -> manifest excluding manifest itself, ledger snapshots and release artifacts -> append archived row pinning manifest -> copy final segment/campaign ledger snapshots -> verification -> release-list pinning manifest and both ledger snapshots. Manifest never includes a ledger snapshot that pins it. Save original ledger tip in archived row/verification; new ledger writes after close invalidate release authorization. New close-id required after any correction.

verify_archive.py traverses the WHOLE graph using ONLY A and raw root, with queue/repo resolution disabled and --forbid C (entire hot tree, not only var). It also validates the H3 chain, closed inventory, latest verdicts, result-to-output bindings, raw/derived mappings and every listed retained object. Missing raw, unmapped cache/source/auxiliary ref, changed config, missing product or rejected/pending verdict => exit 3 and NO release list. Looking up only four output hashes is insufficient.

### 4.4 Release safety, operator only

verify_archive emits release-list under C/close/<close-id> after independent graph verification. Fields include archive manifest Ref, segment and campaign ledger snapshot Refs, pinned frozen inventory, source ledger tip hashes, exact queue-cache candidates {Ref, raw_or_retained Ref, device,inode,size,mtime_ns}, complete validation observations, totals and close-id. Device/inode captured by archive preparation while reading cache, not from archive stat. The list's SHA is posted externally for the operator. Verified booleans are explanatory, NEVER authorization by themselves.

release_hot_cache.py requires --list ABS --expected-list-sha256 <posted SHA> --roots ROOTS --execute and operator context. Acquire close/controller/admission exclusion; confirm no active consumers and same frozen ledger tips. Before ANY deletion: hash list against independent posted SHA, rehash manifest and both ledger snapshots, rerun entire archive/raw graph closure with hot reads disabled, open/hash EVERY cache candidate without following symlinks, verify device/inode/size/mtime/hash and exact allowed cache subtree, and compare candidate set/totals to the verified closed inventory. Refuse on any mismatch, missing raw, changed list/archive/ledger/cache, symlink parent or traversal; all these preflight failures leave every cache file intact. No wildcards, no directory deletion, no hardlink aliases (require st_nlink=1).

Immediately before each unlink repeat no-follow identity/hash checks and confirm its open directory FD still names the same admitted parent; use directory-relative unlink, no resolving a new path after checks. Exclusive ownership/quiescence is a prerequisite: POSIX does not provide atomic compare-hash-and-unlink against a malicious uncooperative writer. If it cannot be assured, refuse, never claim race-proof safety. If an unexpected race/I/O failure appears after some authorized unlinks, stop and report a partial release receipt honestly; no promise of multi-file rollback. The live destructive command is NEVER run by these headless agents. Tests may unlink their OWN synthetic temporary files only. Raw mirror/archive bytes are never deleted or changed.

## 5. Statistics and readiness populations

Producer fields stay verbatim with source Ref and field path; cells depth_m has count/min/max/mean/p80, NOT median/p99. Derived required measurements for map_done: valid_fraction, depth_median_m, depth_p99_m, nodata_fraction, edge_valid_fraction, slope_p99_deg; bounded to admitted terrain/support <=262144 cells. Each measurement is {status:measured|not_applicable|unavailable,value:number|null,reason:null|string,inputs:[Refs],method_version}. No bare ambiguous null.

Neighbour delta is not_applicable with reason=no_geometric_neighbours only when the verified grid has none; it does not flag and cannot inflate a measurement denominator. Missing expected neighbour data is unavailable -> DERIVED_UNAVAILABLE flag. Catalog depth range absent is optional not_applicable/catalog_range_absent, never counted as a successful plausibility test; a stated range that cannot be evaluated is unavailable. Required raster read/derivation failure is unavailable -> flag; no model can override it. For held/unmapped windows raster statistics are not_applicable/pipeline_not_mapped and Tier1=held or unavailable, not pass. Endpoint absent/malformed response/missing visual assessment on map_done => flag, raw response retained; no inferred visual pass. Thumbnail deterministic 256x256, hillshade azimuth315/altitude45, nodata transparent, renderer/version pinned. Model and endpoint capability remain explicitly qualified parameters, not hard-coded proof of vision support.

Let W = ALL distinct admitted inventory windows in the selected cycle/cohort (deduplicate replacement attempts with original inventory key). Missing run summary does not remove W. A = windows with verified acquire.done; Q = verified qualify.done with holds empty. Mandatory invariants Q subset A subset W. Output counts W,A,Q plus acquire-held/failed/pending/missing; acquire-done-without-qualify; qualify-held/failed/pending; map-held; integrity-unavailable and replacement exclusions.

qualify_clean_all_admitted = |Q|/|W|. This ALONE tests the readiness >=95% criterion, with every hold also requiring accepted cause. Zero W => not measured, NOT pass.
qualify_clean_given_acquire_done = |Q|/|A|, labelled conditional; zero A => not measured. Never label this the all-window readiness rate. Optional attempted-qualify metric must be separately named; it never replaces either rate. Unknown evidence contributes no numerator, remains in W, and makes evidence completeness fail.

Controls (one cohort with 4 windows): acquire-held; acquire.done/qualify absent; qualify.done/map held; qualify.done/map done. W=4,A=3,Q=2 => all-admitted 0.5, conditional 2/3; map_done=1; acquisition-held/pending qualify must not disappear. A single mapped isolated window with every REQUIRED measurement available and neighbour status not_applicable can pass Tier1. A mapped window missing a required measurement stays flag even if a reviewer accepts the explanation for record closure; it is NOT a true negative or a quality pass.

Confusion population: only reviewer-examined mapped windows with valid integrity and complete REQUIRED measurements plus definite reference decision. tp=Tier1 flag/reviewer defect; fp=flag/no defect; fn=pass/defect; tn=pass/no defect. Explicit lists/counts: held, unavailable-required, unfinished, invalid-evidence, unexamined, reference-undetermined. Accepted closure cause is not a negative quality label. Optional not_applicable is not exclusion. Report recall tp/(tp+fn), precision tp/(tp+fp), misses=fn, population definition and sampling bias. Zero denominator => not measured. These are examined-population metrics, NOT measured whole-coast recall. A readiness audit must state sampling limits and unmet coverage, never claim 90% detection over unexamined windows.

Readiness outputs, all with evidence Refs:
- hashes/broken receipts from T1/T2/open-report, no invalid evidence counted clean;
- >=95% all-admitted qualification and hold cause dispositions as above;
- screener recall/precision + misses over named examined cohort;
- no sampled must-fix, with sampled count (zero sample is not visual evidence);
- contour/seam visual criterion NOT supplied by hillshade stats: not measured until separately reviewed contour/preview artifact exists;
- N=16 time/bytes requires real PC-6 N=16 run, not dry-run or held receipts;
- review rounds per original plan inventory, median from actual verdicts;
- throughput = distinct final accepted plan inventories / elapsed observation days, not number of corrective verdicts; report mapped and accepted-held throughput separately;
- projection from measured windows/plan/remaining admitted inventory, not guessed plan counts; cache peak across campaign, tokens/latencies measured, missing cost remains unknown;
- operator rescues from board events with scope/period, unavailable if no event export.
Interim pilot files are labelled interim with explicit adapters; absent counts/images/provenance remain unavailable, not silently upgraded to canonical measurements.

## 6. Card lifecycle and tier roles

Per admitted plan: RUN -> T1(local-worker) -> T2 rehash/budgets/neighbours (bounded luna/haiku checks in parallel) -> T2 assemble -> V-/T3 independent semantic reviewer. Every edge is a kernel parent edge, all outputs round/attempt-addressed. Local GPUs do the bounded first pass on every window before T2/T3; no duplicate local queue jobs or assumptions that unavailable image tools work. Operator alone raises concurrency (target 3-4 local slots and swarm widths are measurements, not granted caps). CPU/network mapping and model-review time reported separately.

T3 is a separate card with completed parents, so it never calls request_changes on a RUN parent. It writes verdict then:
- accept: create authorized next admission child (or close-preparation after full inventory closure), complete current V- with evidence, not a publication declaration;
- must_fix: create correction child with exact numbered findings and pins, then fresh r+1 T1/T2/T3 chain. Complete current V- as 'review completed: must_fix', not plan accepted. Content changes require new admission/plan identity; review-only changes retain plan and new round. Third bounce goes to fable-2nd-look, not an endless fourth review;
- external blocker: block current task only for actual unavailable endpoint/medium/required decision that cannot be corrected locally. An integrity defect is corrective must_fix, not an external block.

Scripts print suggested board actions; agents perform them via kanban tools and read back. Do not embed created_card IDs in a prewritten immutable verdict: verdict contains action kind/next inventory authorization; board IDs go in the subsequent handoff. This avoids rewriting verdict bytes after creating cards. Readiness approval remains the Claude operator's; no skill auto-starts long runs, publishes, emails or changes operational routes.
